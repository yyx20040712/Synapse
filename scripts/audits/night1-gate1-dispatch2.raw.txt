## 三、新发现（单列）

### N-1（N 级）：import-gate 的 exit 无下界守卫——非配对 exit 静默转负，可致互斥假阴性释放
证据（import-gate.ts）：
```ts
exit: () => {
  count -= 1        // 无 count===0 守卫/断言
},
inFlight: () => count > 0
```
若未来出现双 exit / exit 先于 enter 的接线 bug，count 转负后**静默**；随后一次正常 enter 仅归 0，`inFlight()` 返回 false——import 实际在途而 workspace 三入口互斥被放行。失败模式是静默的，正是本票要防的类别。注释自承「enter/exit 成对」是先例约定而非机制保证。缓辩：与原闭包语义逐位一致（行为零变承诺内），且当前唯一调用方在 try/finally 内——故定 N 级备案，建议 exit 加 `if (count === 0) throw` 或至少注释声明「负计数=接线 bug 信号」。

### N-2（测试盲区，N-1 对偶）：import-gate 测试未覆盖非配对 exit 路径
证据（import-gate.test.ts）：两用例均为严格配对序列，无「exit 多于 enter」用例。与 N-1 同源，若 N-1 采纳守卫则此处补 1 红证用例。

### N-3（测试盲区，N 级）：INV-39「全量载荷组装」纪律无组件层测试锚
证据（UiScaleSection.tsx:46 + 文件头注释）：注释自述测试面=「e2e smoke 真渲染锚定 + store 面六用例」。store 测试锚的是 save 透传/乱序守卫，**不锚调用方组装了什么**；组件层无单测断言 `save` 被以 `{contactEmail, theme, uiScale}` 三字段全量调用。若未来重构漏带字段（被 zod default 静默填 'small'——注释自认的静默失败面），能否捕获取决于 smoke 是否断言载荷而非仅 toast/rect。**不确定**：smoke 用例本体不在本包内，无法确认其断言面；若 smoke 仅锚 toast+rect，则此纪律实际无回归防线，建议补组件层 save 载荷断言或确认 smoke 断言面后在档。
