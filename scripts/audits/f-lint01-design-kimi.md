# F-LINT-01 设计书：INV-11 lint 机器化锚定

**输入限制声明**：禁接触仓库，token 文件名、常量清单等均为例示假设（标 ⚠假设）。下文"锁定面"=eslint.config.js / check-quality.mjs 受锁，改动需走锁更新流程（流程细节不明，列为开放问题）。

## §1 可检性矩阵（形态×裁决×误报面×归属）

| # | 形态 | 裁决 | 误报面 | 归属 |
|---|------|------|--------|------|
| 1 | 同值双常量（两 const 同字面量） | 可机检（AST 全域收集 const 声明值比对） | 中：`0`/`''`/`100` 等泛值撞车→需最小字面量长度/值白名单 | lint(B) |
| 2 | 常量旁落（NOTE_TITLE_MAX 在而消费处写 200） | 部分可检：仅对**登记清单**内常量可判（值→常量名映射表，消费处命中同值字面量即报） | 低（清单驱动）；泛化"任意导出常量自动比对"跨模块解析成本高、误报中→不做 | lint(B)，清单硬编码于 rule⚠漂移自承 |
| 3 | 重复字面量魔法值（同值 N 处） | 部分可检：计数型关卡 | 高：`0/1/-1/true` 不可避免→仅对长度≥2 数值/≥4 字符字符串、阈值 N≥3 生效 | quality(C) 计数关卡；语义提炼仍人审 |
| 4 | CSS 颜色字面量 vs token | 可机检：全 CSS 扫 `#hex/rgb(/hsl(`，token 文件（⚠假设存在 tokens/theme CSS 定义 `--*` 清单）豁免。**token 清单不硬编码**——从 token 文件 `:root` 块正则提取，消除清单漂移 | 低（豁免面明确）；`transparent`/`inherit` 等关键字天然不命中 | quality(C) |
| 5 | tsx inline style 颜色字面量 | 可机检：JSXAttribute `style` 内对象 Literal 值命中颜色正则 | 低 | lint(B) |
| 6 | 手写两份等价类型 | 拆两刀：**同名 interface/type 跨文件重复**=可机检、误报近零→lint(B)；**结构等价异名**=假阳高（同构 DTO 合法）→不可机检 | 同名刀低；结构刀不可控 | 同名→lint(B)；结构→**人审残留登记** |
| 7 | 文案双份（同中文串两处） | 不可机检：合法复用 vs 双源系语义判断，机器不可判 | 仅做"同串≥8 字符出现≥3 处"报告则有价值但非关卡 | **人审残留登记**；可选 C 出 warn 报告（不阻断） |
| 8 | 新增 CSS 未入 FS_DECL 负锚数组（F-CSS-02 W1） | 可机检且**价值最高**：walk `src/**/*.css` 对每个文件跑 FS_DECL 同五通道正则（与 theme.test.ts 同规则文本化复制⚠双份正则需注明），使锚从"七件硬编码"升"全量文件自动入锚" | 近零（正则经既有测试验证） | quality(C)，**与测试锚分工：测试锚保留七件深检，lint 补全量覆盖缺口** |
| 9 | 跨进程类型双源（shared/ 外重复声明 ipc 契约） | 同 #6 同名刀即覆盖；renderer 内 `window.api` 参数类型重声明可后续加 selector 定向 | 低 | lint(B) 同名刀附带收益 |

## §2 三案对比与选型

| 维度 | A no-restricted-syntax | B 自写 rule（plugins.local） | C check-quality 文本关卡 |
|------|------------------------|------------------------------|--------------------------|
| 表达力 | 单节点模式；esquery 属性正则可匹配字面量值（⚠假设未验），**跨节点断言（同值双声明、常量旁落）不可表达** | 全 AST 表达力，Program:exit 全域收集可跨节点 | 无语义，仅文本/正则 |
| 误报控制 | 弱（无豁免逻辑载体） | 强（白名单/清单内建 rule） | 中（正则豁免面） |
| 维护成本 | 低 | 中（rule 需单测——RuleTester 为 eslint 内置，零新依赖⚠假设 flat config 下可用） | 低（先例现成） |
| 受锁面 | eslint.config.js | eslint.config.js+新增 rule 文件 | check-quality.mjs |
| verify 位置 | lint 段 | lint 段 | quality 段 |
| 适配形态 | 仅 #5 退化版 | #1/#2/#5/#6/#9 | #3/#4/#8 |

**终态选型：B+C 组合，A 否决**（表达力不足且省不下锁面）。分工原则：**TS/TSX 语义形态走 B（lint 段），CSS/文本/全量文件形态走 C（quality 段）**；测试负锚群不动，lint 与测试锚互补不重叠。

**逐形态路由表**：#1→B / #2→B（清单制）/ #3→C（阈值计数）/ #4→C / #5→B / #6 同名→B、结构→人审 / #7→人审（可选 C warn）/ #8→C / #9→B 附带。

## §3 实施分期

**MVP（高置信低误报）**
- C-8：全量 CSS FS_DECL 关卡（灭 F-CSS-02 W1 通道）；
- C-4：CSS 颜色字面量关卡（token 清单自提取）；
- B-5：inline style 颜色 rule；
- B-1：同值双常量 rule（值白名单：忽略 `0/1/-1/''/true/false`）。
- 验收：①红证——植入反例集（第八件 CSS 含违规字号、CSS 直写 `#fff`、tsx style 直写 hex、两 const 同值）逐个触发失败；②存量全仓零误报；③verify 全链绿。

**扩展面**
- B-2 常量旁落清单制（首批仅登记 NOTE_TITLE_MAX 等已锚常量）；
- B-6/B-9 同名类型跨文件重复检测；
- C-3 重复字面量计数（阈值 N≥3，先行 warn 试运行一轮再升 error）。
- 验收同 MVP 双口径；每项独立可回退。

**不做面（显式边界登记）**
- 结构等价类型对比、文案双源语义判定、泛化魔法值检测——人审残留，写入 INV-11 状态注记。

## §4 风险与开放问题（给 deepseek 的攻击面自认）

1. **C-8 正则双份**：FS_DECL 正则将从 theme.test.ts 复制进 check-quality.mjs——本身制造 INV-11 双源。缓解：两处加互指注释+（可选）C 关卡校验两正则文本一致；此自相矛盾点请重点审。
2. B-2 清单硬编码于 rule 文件=新漂移面，与票面"禁硬编码清单"精神张力；自认仅接受"小规模+注释对齐"。
3. ⚠假设未验：esquery 属性正则语法、RuleTester 在 flat config/零依赖下可用、token CSS 文件真实存在且 `:root` 可正则提取、check-quality.mjs 的 walk 是否已覆盖全部 src CSS 目录。
4. 受锁两件的锁更新流程与成本未知，分期可能受其阻塞。
5. B-1 值白名单的边界（如 `2`、`100`）可能漏报真实双源——阈值取值缺数据支撑。
6. C-3 阈值 N≥3 为拍脑袋值，试运行期数据可能推翻。

## §5 INV-11 升格措辞建议

> INV-11：类型/颜色/文案/数值单一真相源。**强制方式=机器锚定+人审残留**——机器面：lint 段（同值双常量/常量旁落清单/inline 颜色/同名类型重复，本地 rule 零依赖）+quality 段（全量 CSS FS_DECL 关卡含新文件自动入锚、CSS 颜色字面量 token 清单自提取）；人审残留面（显式登记不可机检）：结构等价异名类型、文案双源语义判定、泛化魔法值提炼。状态=**已锚定（机器面）/部分（人审残留面在册）**。
