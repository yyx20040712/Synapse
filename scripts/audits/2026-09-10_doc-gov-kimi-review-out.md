# 双源审查结论：08 文档治理件 + WP 适配任务书

## B 级（阻断实施）

**B1｜产物二 §0 禁令2 vs 阶段0a/0c：裁决前动正文，自相矛盾**
禁令2 字面为"裁决前禁动**任何**正文（阶段 1 末为硬停点）"，但阶段 0a 改宪法 §0.1 盘点标注、0c 向 AGENTS.md 插入 ORG-SEG 段——两处均在裁决前改动宪法正文。要么禁令2 需显式豁免"阶段 0 三项动作属预授权、不在三选一裁决面"，要么把 0a/0c 挪至裁决后。现状下代理可援引阶段 0 先例主张"裁决前改宪法有授权"，红线出现可绕口子。
**建议修正案**：禁令2 应改写为"除阶段 0 列明动作外，裁决前禁动任何正文"。

**B2｜产物二 §5 模板 vs 全任务书：org-config 项目覆盖件被声明为唯一真相源但无任何创建步骤**
ORG-SEG 段声明"供应商事实唯一真相源=org-config（项目覆盖件 .zcode/org-config.json）"，但阶段 0~2 均无创建该文件的动作，必读清单亦无 org-config 范式件路径。阶段 0c 一旦执行，宪法立即指向一个不存在文件=指针死链，且与 08 §1"供应商事实禁止硬编码于 .md"形成无承接者的悬空——真相源地址簿第一行即失效。
**建议修正案**：阶段 0 应增列"依技能 06/org-config 默认件生成项目覆盖件"一步，或模板措辞改为"默认件兜底、覆盖件待建"。

## W 级（应修）

**W1｜产物二 阶段1：映射表起草缺比对基准**
"逐件对照技能 08 §1 出三选一"要求识别"与技能 references 重复的通用原理段"，但阶段 0b 与 §3 必读清单仅含 08、05，未含 01~07。零上下文会话无 01~07 全文作比对基准，"重复段"判定无依据。建议：必读清单补 references/01~07（或明确 `/ai-dev-org` 加载即含全量 references 可读）。

**W2｜产物二 阶段2"门禁全绿"无命令**

**W3｜产物二 阶段1 盘点范围歧义**
"docs/ 全子树"与括号内 11 件枚举并列——枚举是闭集还是示例？若 docs/ 下有枚举外文件，两读冲突。且 08 §2 要求"项目根全部 .md 群"，本件仅列 AGENTS.md、README.md，未声明根目录无其他 .md（§7 环境事实未覆盖）。08 自云"漏一件=中间态双源"，此处正是漏盘死角。建议：改"全子树（枚举为 2026-09-10 快照，以开工日实扫为准）"，并补根目录 .md 全量确认步骤。

**W4｜提交边界未定义**
阶段 0 改动（ORG-SEG、org-delta 首行）何时提交未说明；阶段 2 要求"单一提交+git diff 零历史件改动"。若阶段 0 已先行提交，阶段 2 的 diff 范围是哪一段？建议：明确"阶段 0 改动并入阶段 2 单一提交"或"分别提交、diff 覆盖两提交"。

**W5｜产物一 §1 寻址表自违单一真相源**
"进程状态"列三源并列（台账/registry/最新交接书）、"用户裁决原文"两源并列（台账/ADR），未给分工判据——寻址表自身制造双源。另"通用工作法住 01~07"排除 08 自身，08 内的治理方法沦为何类事实无址可寻。建议：并列源补主从/分工注记；通用工作法范围改"01~08"。

**W6｜产物一 §2 三选一存在第四态死角**
同一件文档兼有项目硬规则（承接面）与通用原理复述（指针化面）时——AGENTS.md 即典型——三选一无法表达"部分指针化"。映射表对 mkdocs.yml（配置而非事实文档）的分类语义亦不明。建议：三选一外增"拆分/段级处置"选项，或明确件级分类+段级动作两层结构。

**W7｜产物一 §2 步骤4 在产物二无落地**

**W8｜产物一 §4 日常体检的裁决通道缺失**
"候选废弃入映射表待裁"——§2 裁决流程是适配战役的一次性场景；常态化体检产生的候选件走何通道呈报裁决、是否累积批裁，未定义。建议：补"体检候选件攒批呈报"或"随战役收口一并裁决"的通道条款。

**W9｜词汇映射表挂宪法头部的预算归属未明**
08 §2 与产物二阶段 2 均要求映射表挂宪法头部，但宪法有预算自检（ORG-SEG ≤600 字符）。映射表是否计入预算、计入哪段，两件均未言明；若计入且无豁免，阶段 2 可能必然 FAIL 且"禁删条款"下无解。建议：08 明确映射表预算口径（豁免或单列额度）。
