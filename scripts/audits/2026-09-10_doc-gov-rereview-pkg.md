## 1. 事实分层寻址表（哪类事实住哪——双源漂移的根治面）

## 2. 多项目归并指针化手册（四步）

1. **盘点映射**：项目文档群逐件对照 §1 寻址表，产出**全量映射表**——
   漏一件=中间态双源。盘点范围=项目根全部 .md 群+docs 子树（以开工日
   实扫为准，快照清单仅为索引）。**件级四态+两类登记**：
   - **承接**=项目真相源保留（硬规则/环境/契约类事实）；
   - **指针化**=整件为通用原理复述 → 改指针+一行项目差异注记；
   - **拆分**=件内混装（项目特有段+通用复述段，宪法即典型）→ 段级
     处置：特有段承接、复述段指针化；
   - **废弃**=过时件 → 归档三件套（重定向页+字节校验快照+迁移清单，
     形态范例=技能归档件 `_archive/loop-engineering-archive-2026-09/`）；
   - **登记·历史归档件**=已入档过程记录 → 原样登记免处置（§3 红线）；
   - **登记·配置件**（mkdocs.yml 等）=不入映射表，仅登记导航/引用变更。
2. **裁决**：四态选择属用户裁决面（裁决权限三分法负面清单）——代理
   只起草映射表呈报，**禁代裁、禁裁决前动正文**（战役预授权明列动作
   除外，预授权须逐项列明于任务书）。
3. **一次性执行**：裁决后在**单一提交**内完成全部处置（禁分批渐进
   ——中间态=双源最长暴露窗）；有 grep 门禁的项目加装「指针化对照」
   检查（正文中与技能 references 重复的通用原理段=红，白名单登记例外；
   豁免须呈报理由入 org-delta）。
4. **机检兜底**：已插 ORG-SEG 段的项目必跑预算自检；收口核对基线
   HEAD 与历史件哈希锚（见 §3）。

**词汇差异处理**：项目与技能的术语差=新增**双向词汇映射表**挂宪法
头部、置于 **ORG-SEG 标记段之外**（**不占** ≤600 预算——预算脚本只
数标记段内），历史原文零改动——映射表是桥，不是改写令。

## 3. 历史件禁改写红线

- **适用面**：一切已成档的过程记录——旧交接书/briefs/审计档/战役报告/
  已并入 git 历史的文档/commit message。
- **理由**：它们是审计链与决策溯源的载体（P7/D2）；改写比删除更糟
  ——删除在 git 历史仍可考，改写制造「当时就是这么说的」伪证。
- **机检形态**（防 amend/rebase 伪证——git diff 对改写历史盲）：批次
  开工记录基线 `git rev-parse HEAD`+关键历史件 sha256 锚；收口核对
  HEAD 祖先链形未变+锚定哈希零变动。
- **唯一合法动作**：追加（新文件/新段标注日期）或归档；发现历史件
  有错 → 新增勘误件引用原 file:line，**禁原地修改**。
- 新写文档引用历史词汇时用映射表括注（如「闸（=门审授权）」）。

## 4. 文档腐化体检（触发式+定期）

- **触发式**：技能 references 版本升级或项目宪法修订后，对照 §1 寻址表
  扫指针化漂移——被指文件还在吗/内容还匹配吗/新增了正文抄写吗。
- **定期**：每战役收口随教训回流查四项——①台账引用的基线数字与宪法
  口径一致且指针零死链 ②双源复发扫描（新写的通用原理段落）③stale
  文档（连续两战役未引用且内容过时=候选，入映射表）④预算自检 PASS。
- **裁决通道**：体检产出的候选件**随战役收口一并攒批呈报**（复用
  映射表裁决通道，不另设）；体检结论一行入项目账本（`event=doc-health`）。
