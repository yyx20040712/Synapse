## A. 六判据逐条攻击

- **判据一 [W]：同名同值 ≠ 同一概念；“异名同值=负收益”反例存在。**
  - 模块作用域让“同名”成本很低。两个无关模块可以恰好都写 `const PAGE_SIZE = 4096`，一个是 UI 分页，一个是内存页；合并成一个共享常量后，任一方改值会静默影响另一方，与组 8 的 `15_000` 危害完全一样。
  - 组 8 只能证明“跨语义耦合有害”，不能推出“同名同值跨文件就是同一概念”。同义词异名（如 `ACTION_FAILED` / `OP_FAILED`）也可能本就是同一语义，未必都负收益。
  - 因此“红层 6 组真命中、误报 0”是对当前 18 组的过滤结果，不是算法保证；未来同名但异域的新增命中仍会误报。

- **判据二 [N/W]：trivial 集与票面一致，但“绝对豁免不看名字”偏宽。**
  - `''`/`-1` 在某些场景是有语义的哨兵值，例如 `NO_SELECTION = -1`、`EMPTY_PREFIX = ''`。两文件同名同值也不会报，等于承认了一类可集中定义的重复。
  - 若这是票面白名单的本意，则可接受；但它不是“过滤噪音”，而会漏掉少数有价值命中。建议在终裁中明确写为“宁可漏报也不增加噪音”的策略，而不是“自然合理”。

- **判据三 [W]：warn 阈值是经验值，且与“文案不豁免”的宣称不一致。**
  - 组 9 `'ai-sensor'` 是异名同文案，只因为它不是 CJK 且没有空格分词，就完全不出 warn；这与“文案不豁免、异名同文案入 warn”不一致。
  - 阈值“长度 ≥4 且含 CJK，或 ≥2 空格分词 token”会漏掉 kebab-case/URL/资源 ID 等重复文案，也会放出一批长度刚好 4 的 CJK 通用词。上线后噪音评估不能被“CI 不阻断”掩盖。

- **判据四 [W]：同文件豁免与 Rule of Three 口径冲突。**
  - 红层 6 组真命中每组只涉及 2 个文件、2 个声明点；若按 Rule of Three，两处不应触发抽取共享常量。设计却说跨文件 2 处即红。
  - “文件内可见性高，作者知情选择”不是 Rule of Three，而是“文件内豁免”的另一种理由。所以要么改为“两处即抽是项目约定”，要么不要引用 Rule of Three。

- **判据五 [B]：票面明确的“常量名前缀规则”被单方面取消，不能直接略过。**
  - 票面授权面包含“常量名前缀规则”，设计书 §0.2 判据五以“唯一定义点替代”取消了它。这是授权边界外否决，不应混在“六判据”里默认成立；至少应作为终裁请示项单列。
  - 若终裁仍要求前缀规则，案 A/B/C 的收集/报告层都要加“共享常量命名约束”逻辑，成本估算会变化。

- **判据六 [W]：收集层与“按 AST 值归一化”自相矛盾。**
  - 判据六说要处理 `15_000`/`15000`、引号差异，但收集层只收 `Literal` 或一元负号 `Literal`。
  - 无表达式模板串 `` `foo` `` 在 AST 中是 `TemplateLiteral`，不是 `Literal`；`as const`、`satisfies` 包裹的常量初始值也不是 `Literal`。这类同值常量会被静默漏掉。
  - computed key / 对象常量也不在收集范围。若票面只按“字面量 const”意图收，现有描述没有排清这些边界。

## B. 18 组定性复核

- **总体 [W]：无法独立复核。**
  - 所有 18 组结论都来自未随票交付的 dry-run 扫描器；“138 个声明”是否包含 `as const`、模板串、导出声明等，设计书自己也列为不确定项。
  - 因此“误报 0”“真命中 6”都应视为待对拍结论，不能作为终裁事实。

- **组 1、14 [W]：**
  - 异名同文案降 warn 是合理方向；但组 1 有 7 个文件，是否真全是“复用噪音”而没有“应统一文案”的收益，需看源码语义。当前无源码不能确认。

- **组 2–11（除 8/9）[W]：**
  - 按“异名同值不红”的判据会被过滤，定性一致；但把它们全部定为“数字巧合/误报”是 dry-run 的价值判断，本审核看不到引用与作用域，不能背书。

- **组 8 [W]：**
  - `HTTP_TIMEOUT_MS` vs `READING_TICK_MS` 确实语义不同；但“收敛反而有害”只对这两个名字成立。它不能作为“所有异名同值都负收益”的普遍证据。

- **组 9 [W]：**
  - 它暴露 warn 阈值问题：`'ai-sensor'` 与 DIR_NAME/SKILL_NAME 的语义相邻度并不低，却因无空格/非 CJK 不出 warn。若 C-3 要收重复字面量，这里是漏收点。

- **组 12/13/15/16/17/18 [W]：**
  - 从表内信息看，它们是“同名同值”候选；但按判据一的缺陷，仍不能证明“同一概念”。尤其组 15/18 是 className 字符串，若分别处于不同组件且未来样式独立演进，合并同样会造成耦合。
  - 需要 file→feature 归属、是否 import/export、声明上下文才能判定“真命中”。

## C. 三案架构风险

- **案 A [W]：静默失败面最小，但“baseline 棘轮”绕过敏并不充分。**
  - A.3 让红层命中与 baseline 求差，baseline 文件可被 PR 直接增加新指纹；所谓“存哈希而非名单”只提高修改噪音，不阻止添加。若不强制“baseline 只减不增”或对新增指纹给出机器可审理由，棘轮是纸糊的。
  - 先红证只有简单字符串案例，没有 `template literal`/`as const`/进制/分隔符/同文件豁免/trivial 豁免的矩阵，无法支撑判据六与四。

- **案 B [B]：不推荐。**
  - B.4 建议 manifest 过期时 fail-closed，但不能覆盖 ESLint `--cache` 命中导致规则完全不执行的情况。规则不跑，fail-closed 就没有触发点，正是设计书担心的静默漏报。
  - B.6 的自陈“未实测”意味着案 B 的主风险没有验证；同时触碰 eslint.config.js，受锁面高于票面最小路径。除非先补 spike，否则不应终裁选 B。

- **案 C [B]：本票投反对。**
  - 为一张红层规则建 code-index 层，并新增 ts-morph 生产级 devDependency，属于过度工程。
  - C.4 的自证“植入已知常量后断言索引记录数 +1”只能证明冒烟路径可用，不能证明索引不会漏收其他语法；所谓自证缓解“系统性静默失败面”不成立。

## D. 推荐案 A 的终裁风险

- **[W]：案 A 是可接受方向，但不是当前版本。**
  - 挂 check-quality 而避开 eslint.config.js，与票面“eslint.config.js 或 check-quality”相符，受锁面小，失败发生在 CI/verify 链上。但独立脚本没有 IDE/行内豁免通道；出现误报时必须改 baseline，这又放大了 baseline 被编辑放行的风险。
  - 维护成本上，它需要自行维护 ignore 规则（`.test.`、生成物之外还有 eslint 全局 ignore），没有说明这些边界，长期可能与 eslint 忽略面漂移。
  - A.1 列出 `collect-constants.mjs`、`report.mjs` 与 `dup-constants.mjs`，A.6 又说“两文件”，文件清单不一致，成本基线与受锁面需澄清。

## E. B-2/C-3 合派与 B-6 另立

- **B-2 [W]：半合派可接受，但“零成本副产物”表述过强。**
  - 若只是导出“未被共享引用的字面量 const 清单”，收集器确实可低成本产出一部分；但“是否被共享引用”涉及 import/export 分析，不是纯收集层必然能力。
  - 以只读 artifact、不卡 CI 交付是好的边界，不应在本票内给它的消费定规则。

- **C-3 [B/W]：不应以“同票尾声增量”顺带收口。**
  - 行内重复字面量 warn 与模块级 const 是不同数据面，需要单独的 false-positive 控制（例如不能对类型、枚举 key、对象 key 等误报）。现有 warn 阈值完全没为行内场景设计。
  - 如果票面明确只做“const 声明同值”，把 C-3 并入会扩大终裁；如果票面包含 C-3，应单列规则设计。

- **B-6 [N]：另立是恰当的。**
  - 类型空间同名与值空间收集器零复用，B-6 单独终裁不会阻塞本票。

## F. 自陈不确定项是否隔离

- **1（案 B 缓存交互未实测）[N]：**
  - 既然推荐案 A，案 B 的未测风险不阻塞 A；但最终若选 B，必须先做 spike，这本设计已写明。

- **2（dry-run 扫描器未随票）[B]：**
  - 这不是可隔离的边角项，而是所有 18 组定性的起点。没有扫描器源码或输出快照，“dry-run 为金标准对拍”无从执行。应在案 A 实现前补交 dry-run 数据包（脚本或 JSON 输出），否则无法验证“存量零误报”。

- **3（warn 阈值噪音）[W]：**
  - 作为上线后观察项可接受；但它实际上已经被案 A 的结构“只打印不阻断”降级为无责任警告，容易无人跟进。

- **4（baseline 文件路径变化）[W]：**
  - 路径变化导致 baseline 随 PR 更新是有意设计，但也为“编辑 baseline 放行新增”开了一条合法通道。若没有机器强制“只减不增”，这个不确定项不能算被缓解。
