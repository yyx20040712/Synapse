## 问题条目

### W1 — 用例③「深断言」不能失败：filter①（busy=false 忽略）实际无红证锚定，报告 §七-5 方法论申报不成立

证据链：
- ImportDropZone.tsx diff（runImport 入口）：`sessionRef.current = null` / `busyRef.current = true` / `setBusy(true)` / `setProgress(null)` —— **每次新会话入口无条件重置 sessionRef**。
- import-dropzone.test.tsx 用例③注释自述：「idle 事件若写了 state 或锚定了会话身份，后续本会话首事件会被异身份过滤误吞——此处必须照常更新」。

推演：设想变异「删 busy 门但保留锚定」（idle 事件写 state+锚定 `sessionRef='stale'`）。用例③随后 `click('导入 PDF 文件')` → runImport 同步段先把 `sessionRef.current = null` 抹掉 → `live2` 事件到达时 sessionRef 为 null → 重新锚定 `live2` → 照常 setProgress → 断言 `复制文件（1/1） 新会话.pdf` **通过**。即该「深断言」对它声称要锁的变异恒绿；setProgress 写入又因既有渲染门（busy 门 :138）不可观测。结论：票面 §一B 的 filter①（busy=false 时 state 不写）在本设计中**组件级不可证伪**，M2 只锁 filter②。正确处置是报告如实改报「filter①=渲染门之外的内部质量门，无机器锚」（类似 INV-49 噪声面的「部分锚定」口径），而非申报一个推演不成立的代理断言。代码本体行为正确，故不定 B。
