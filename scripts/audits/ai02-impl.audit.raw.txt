```ts
function createDomCanvas(width: number, height: number): RenderCanvas {
  const el = document.createElement('canvas')
  el.width = width
  el.height = height
  const ctx = el.getContext('2d')
  if (ctx === null) throw new Error('canvas 2d context 获取失败')
  return {
    width,
    height,
    ctx: ctx as unknown as CanvasRenderingContext2DLike,
    drawFrom(src, box) {
      ctx.drawImage(
        (src as { el?: HTMLCanvasElement }).el ?? (src as unknown as HTMLCanvasElement),
        box.sx,
        box.sy,
        box.sw,
        box.sh,
        0,
        0,
        box.sw,
        box.sh
      )
    },
    toPngBase64(): string {
      const dataUrl = el.toDataURL('image/png')
      return dataUrl.slice('data:image/png;base64,'.length)
    }
  }
}
```

`ctx.drawImage` 的第一个参数类型是 CanvasImageSource。`(src as { el?: HTMLCanvasElement }).el` —— `src` 是 createDomCanvas 返回的对象 `{ width, height, ctx, drawFrom, toPngBase64 }`。这个对象没有 `el` 属性，所以 `.el` 是 undefined。`??` 左侧 falsy，取右侧 `(src as unknown as HTMLCanvasElement)`，即把该普通对象强转成 HTMLCanvasElement 传给 drawImage。drawImage 内部会检查参数是否是 CanvasImageSource，如果不是，抛出 `TypeError: Failed to execute 'drawImage' on 'CanvasRenderingContext2D': The provided value is not of type 'CanvasImageSource'`。因此生产路径必然抛异常。这个异常发生在 for 循环内的 `annoCanvas.drawFrom(pageCanvas, box)` 中。`runExtraction` 的 try/catch 会捕获，发送 error 载荷，提取在第一个有标注的页失败。如果没有任何 anno.rects 匹配当页，则不会调用 drawFrom。但如果文档有标注，失败。所以 BLOCKING 正确。

修复建议：修改 RenderCanvas 接口增加 `el: HTMLCanvasElement`（或 `get canvas()`），在 createDomCanvas 返回中暴露 el，drawFrom 使用 `src.el`。或者更简洁：`drawFrom` 直接接收 `sourceCanvas: HTMLCanvasElement`，但接口抽象会变。也可以让 `createDomCanvas` 返回的对象包含 `el` 并在 drawFrom 中使用。注意测试 stub 也需要加 el 字段（可以 mock 空对象），否则类型错误。

另一个可能修复：在 drawFrom 中 `const srcCanvas = (src as unknown as { el?: HTMLCanvasElement }).el ?? (src as unknown as HTMLCanvasElement)`，并把 `el` 暴露在 createDomCanvas 返回对象中。建议。
