### WARN（W 级）

**【W1】单测「初始态」用例自证恒真——store 真实默认值失锚**
- 位置：`tests/unit/renderer/corpus-export.test.tsx:157-167`（用例本体）+ `:138-145`（beforeEach `resetStore`）
- 论证：用例断言 `useCorpusExportStore.getState()` 的初始值，但 beforeEach 的 `resetStore()` 已用测试自带的字面量 setState 覆盖过——断言的值永远是 resetStore 写入的值，**自证**。具体失败场景：有人把 store 默认 `busy: true`（corpus-export.store.ts:57），16 个单测仍全绿；唯一防线是 e2e（按钮点不动→60s 超时红），定位成本高且慢。违反宪法「恒真断言=假阳性，比没测试更危险」的测试纪律精神。
- 修复建议：文件顶层（beforeEach 首次执行前）捕获 `const initialSnapshot = { ...useCorpusExportStore.getState() }`，初始态用例改为断言 `resetStore()` 后 `getState()` 深等于 `initialSnapshot`——锁定「重置值≡真实初始值」，默认值改动即红。注意该文件已入 locks manifest，补测属受锁变更：`locks:unlock` → 改 → `locks:apply`，提交带 `[locked-change]`。

**【W2】`sendItem` 映射的 not-ok 分支无测试锚定——该分支是防会话死锁的关键接线面**
- 位置：实现 `src/renderer/features/settings/useExportCorpusEvents.ts:40-43`；测试 `tests/unit/renderer/corpus-export.test.tsx:264-272`（仅测 `r.ok` 为 true 的路径）
- 论证：映射 `return r.ok ? { ok: true, data: undefined } : r` 若退化为无条件返回 ok（重构事故面），corpusItem 的折叠拒绝（如 INVALID_REQUEST）会被吞成成功 ack：提取器以为 complete 成功→destroy→idle，main 侧永远等不到合法终局→**会话悬挂、无 toast、按钮永久 busy**——正是 deferOutcome 所修的同族死锁的镜像面。当前实现正确，但合约未锁。
- 修复建议：生产组装用例补一条断言——`stubApi.export_.corpusItem.mockResolvedValue({ ok: false, error: { code: 'INVALID_REQUEST', message: 'x' } })`，`await deps.sendItem(item)` 结果 `toEqual` 该 not-ok 形状。同 W1 受锁流程。

### NIT（N 级）

**【N1】`applyProgress` 不校验 sessionId——跨会话迟到 progress 可短暂污染新会话进度显示**
- 位置：`src/renderer/features/settings/corpus-export.store.ts:84-87`
- 论证：busy 守卫只挡「终局后迟到」，挡不住「会话 A 的迟到 progress 在会话 B 在途期间到达」（事件通道与 invoke 回复无序，窗口极窄）。影响仅限进度行数字短暂错乱——终局源=invoke resolve（INV-11），最终一致性不受损。建议：store 增存当前 sessionId（progress 载荷已带），不匹配即忽略；非必须。

**【N2】`failSession` 无 `session === s` 守卫**
- 位置：`src/main/services/export_/corpus.export.service.ts:276-281`（配合 :287-293 deferOutcome）
- 论证：理论误杀面（悬挂 deferOutcome 抛错时把新会话的单飞锁置 null + 二次 reject）已被提取器串行协议结构性排除（见 B 级候选 4 推演）。建议防御性加 `if (session !== s) return` 一行，使不变量不依赖跨进程协议成立——与该文件「同步摘牌防窗内双推进」的既有防御风格一致。

**【N3】e2e PNG 体积下限断言（>1000 字节）依赖渲染产物体积**
- 位置：`tests/e2e/corpus-export.spec.ts:190`
- 论证：纯白背景+少量文字的 PNG 在 pdfjs/字体栈变化后可能跌破 1KB 造成误红（当前真跑绿）。建议改为 PNG magic + `length > 0` +（如需）IDHR 宽高解析断言；非阻塞。

**【N4】日期口径不一致：注释/登记多处 2026-08-27，系统日期与 locks manifest 为 2026-08-26**
- 位置：`corpus.export.service.ts:285`、`CorpusExtractor.ts:276`、`docs/invariants.md` INV-14/18 回写行、`tests/unit/services/corpus.export.test.ts:46`（now 桩）vs `locks/manifest.json` generatedAt `2026-08-26T00:00:26Z`
- 论证：审计记录与事故溯源依赖日期一致；若是时区/笔误建议统一。不影响正确性。

**【N5】`safeName` 洗涤碰撞面：不同 annotationId 洗涤后同名会互相覆盖**
- 位置：`src/main/services/export_/corpus.export.service.ts:383-388`
- 论证：如 `a/b` 与 `a_b` 洗涤后同名，manifest figures 出现重复路径。annotationId 为应用生成 UUID，实际碰撞面为零——纵深防御自身的小缺口，登记即可。
