### [B-1] crop 模式两图尺寸不等时退出码=2，与票面退出码合同“尺寸不等 exit 1”不符

**证据**（visual-diff-locate.mjs 完整 diff）：

- crop 页内函数对尺寸不等直接抛普通 `Error`：
  ```js
  throw new Error('两图尺寸不等: baseline=' + W + 'x' + H + ' after=' + ...)
  ```
- 主 catch 对所有非 `ToolError` 统一记退出码 2：
  ```js
  exitCode = e instanceof ToolError ? e.code : 2
  ```
- 因此 crop 模式下两图尺寸不等时实际退出码为 **2**，不是票面/简报预裁要求的 **1**。
- 差分模式是通过 `sizeMismatch` 对象 + `bail(1)` 显式处理的，退出码正确；crop 模式未做同样映射。

**对照票面**：简报预裁“③.3 两图尺寸不等=FAIL 报错”“⑥ 退出码：参数错/文件缺=2，尺寸不等=1”，退出码合同未限定差分模式；crop 模式同样要对比 baseline/after 两图，尺寸不等仍属“对比前提破坏”，应 exit 1。  
**不确定性**：预裁未明确写出“crop 模式尺寸不等也 exit 1”，我据此推定合同为全局一致。若主控确认该合同仅面向差分模式，可将本条降级为 W；否则为 B。

### [W-1] `absDir` 用 `existsSync(join(r,'.'))` 无法区分文件与目录，传文件路径会触发未捕获异常且退出码非 2

**证据**（visual-diff-locate.mjs 完整 diff）：

```js
const absDir = (p, label) => {
  const r = isAbsolute(p) ? p : resolve(process.cwd(), p)
  if (!existsSync(r) || !existsSync(join(r, '.'))) fail(2, `${label} 目录不存在: ${p}`)
  return r
}
```

`path.join(r, '.')` 经规范化后等于 `r` 本身；对**已存在的普通文件** `existsSync` 也返回 true。因此若用户把 PNG/JPG 文件路径当作目录传入：

- `absDir` 不会触发 `fail(2)`；
- 后续 `await readdir(baselineDir)` 会对文件调用目录读取，抛出未捕获异常；
- 进程以 Node 默认未捕获异常退出码（通常 1）退出，而非合同所定“参数错/文件缺 exit 2”。

**建议**：用 `statSync(r).isDirectory()` 替代 `existsSync(join(r,'.'))` 的目录判断。证据日志仅覆盖“不存在目录/空目录/正常目录”，未覆盖“目录参数传文件”。

### [W-2] `mkdtemp` 与 `chromium.launch` 位于 `try/finally` 之外，异常路径存在临时目录/浏览器资源泄漏

**证据**（visual-diff-locate.mjs 完整 diff）：

```js
const tmpDir = await mkdtemp(join(tmpdir(), 'vd-locate-'))
const browser = await chromium.launch({ headless: true, args: [...] })
let exitCode = 0
try {
  ...
} finally {
  await browser.close()
  await rm(tmpDir, { recursive: true, force: true })
}
```

若 `mkdtemp` 成功后、`chromium.launch` 抛错（如浏览器二进制缺失、端口占用等），执行流不会进入 `try`，`finally` 不会执行：

- `browser.close()` 无从调用（browser 变量未就绪）；
- `rm(tmpDir)` 不会执行，临时目录 `vd-locate-*` 残留。

**对照实现者报告自裁③**：报告称“运行期错误经 ToolError→catch→finally 清理（browser.close+临时目录删除）”，但 launch 本身不在该保障路径内，自裁描述与实际代码行为不完全一致。  
**不确定性**：该泄漏仅在浏览器启动失败等异常路径发生，常规运行不受影响，故定为 W 未定 B。

### [N-2] 页内字面量 16/6/4 与 Node 侧 `BLOCK/TH/CNT` 存在双写漂移风险（已注记但无守卫）

### [N-3] crop 模式下，位置参数中的态清单若被传入会被静默忽略

**证据**（visual-diff-locate.mjs 完整 diff）：

```js
if (pos.length < 2 || pos.length > 3) { fail(...) }
...
return { baselineDir: pos[0], afterDir: pos[1], statesArg: pos[2] ?? null, ...opts }
```

crop 分支只用 `args.cropState`，从不读取 `args.statesArg`。若用户仿照差分模式顺带传入第三个态清单参数，工具不会报错但会忽略它；该场景易造成“用户以为只对某几个态校验文件，实际全不校验”的误解。建议 crop 模式若收到非空 `statesArg` 即按参数错误处理，或至少在 help/console 中提示忽略。
