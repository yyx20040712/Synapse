## 2. Findings 分级清单

### BLOCKING

### WARN

**WARN-1｜INV-37 “保持”与“弱化”同稿矛盾，且弱化未进 §0 拍板清单**

- 位置：§0 三案一表“所见即所存 INV-37”行；§4 对比表同列；§6 R3⑤。
- 问题：§0/§4 写作“所见即所存 INV-37 **保持**”，§4 修订面又写“INV-37 仅调度条款”；但 §6 R3⑤ 明确写“INV-37 语义弱化显式登记：拖选期视觉=**所见≈所存**”。两种断言不能同真。用户若只看 §0 拍板，会以为 B 案不碰所见即所存语义；而事实上 B 案成立的前提恰恰是这次语义弱化。
- 证据：修订稿 §0：「所见即所存 INV-37 | 保持（快路径同一几何管线；松手瞬间快→settle 可有贴边级跳变……）」；§6 R3⑤：「**INV-37 语义弱化显式登记**……快路径几何为 settle 权威的瞬态近似」。
- 修正建议：§0 与 §4 的“保持”改为“**拖选期弱化为≈，松手/保存时刻恢复严格**”；并把“允许 INV-37 拖选期弱化”列为 §0 用户拍板第④点，不能只藏在 R3 修订段。

**WARN-2｜evaluateVisual 的数据链路未闭合：raw clientRects 无法凭空产出 bands/缓存**

- 位置：§5.1 selection-evaluate.ts 行：“raw range clientRects→同源 merge→缓存 bands”。
- 问题：现行 setPaint 的 bands 来自 `bandsForTextNodes(range.textNodes.map(t => t.node), pixelBoxOf(textLayer))`（SelectionLayer.tsx）。从“raw range clientRects”得不到被选中的 span/textNodes 集合，也就无法首次建立或随选区增长更新 band 缓存。§3.4 第 1 条只说“textNodes 改由 Range 子树父元素枚举替代”，但没有把它放回 evaluateVisual 的链路描述和 tick 预算里。实现者若照抄 §5.1 的链式描述，会做出一个“无法产出 bands”的快路径，或被迫重新引入全页枚举。
- 证据：SelectionLayer.tsx `setPaint({ root: anchorRoot!, rects: anchor.rects, bands: range !== null ? bandsForTextNodes(range.textNodes.map((t) => t.node), pixelBoxOf(textLayer)) : [] })`。
- 修正建议：在 evaluateVisual 描述中显式加入“增量维护被选 textNodes/span 集合”步骤，并说明首次与跨帧增长时的枚举口径；tick 预算同步增补该成本。

**WARN-3｜快路径“raw clientRects”未写清到像素归一化基准的换算**

- 位置：§5.1 selection-evaluate.ts 行。
- 问题：`range.getClientRects()` 返回的是视口坐标；SelectionPaint 消费的是相对 textLayer 盒的百分比 rects（`r.y * 100%`）。快路径链“raw range clientRects→同源 merge”若直接把视口坐标交给同一 merge 函数族，和 settle 路径的归一化基准不一定同盒。§5.1 守卫条款只有一句“归一化基准=选区所在页 textLayer 的 pixelBoxOf”，没有把它放进快路径转换链。
- 证据：修订稿 §5.1「evaluateVisual（快路径：raw range clientRects→同源 merge→缓存 bands）」；SelectionPaint `style={{ top: r.y*100%, height: r.h*100% }}`。
- 修正建议：写成“视口 clientRects → pixelBoxOf(textLayer) 归一化 → 同源 merge → 缓存 bands”，与 settle 路径共用同一坐标系。

**WARN-4｜F-A6-a 探针无法从 DOM 侧直接读 page.rotate，脚本前置条件未定义**

- 位置：§2.2 探针脚本“环境段：page.rotate 值”。
- 问题：设计声称注入 Electron devtools/e2e evaluate，但 `page.rotate` 属于 pdf.js page/viewport 对象，通常在模块闭包或 PdfPageCanvas 内部，不在 DOM 上。包内没有任何暴露 `page.rotate` 的运行时钩子或 `__pdfPage` 之类面的证据。若无临时暴露面或测试钩子，单靠通用 evaluate 脚本拿不到 T1 核心证据。
- 证据：Kimi 裁决已指出 PdfPageCanvas.tsx:111 的 viewport 含 rotate，且该文件不在包内；文本层 DOM 只有 .textLayer/canvas。
- 修正建议：F-A6-a 票面首段先定义 page.rotate 取证注入面（测试构建临时 expose、e2e 内直接调 pdfjs API、或 devtools 断点闭包方案），再写落盘脚本；不能假定脚本“注入即得”。

**WARN-5｜G2 降级门阈值与检测器验收标准缺失**

- 位置：§2.3 G2；§1 S9；§5.4 F-A6-a。
- 问题：“clientRects 与 textLayer 盒偏离率超阈”中的阈值、偏离率定义、在快路径每 tick 的执行成本均无基准；且 S9 是“设计新增”的正式态，却没有对应判定输入。取证若只修好 T1/T2/T3/T4/T7，且不复现 T5 系统性溢出，则 G2 是否落地、以何阈值落地将完全悬空。
- 证据：§2.3「检测器（选区 clientRects 与 textLayer 盒的偏离率超阈）→抑制 paint 渲染」。
- 修正建议：把 G2 阈值与检测器验收标准列为 F-A6-a 取证票的必需交付物；若取证未发现不可修复形态，则在 F-A6-b 票面声明 G2 仅在新增复现证据时启用，避免“检测器先写但永远无阈值”。

## 4. 独立发现的新问题面（Kimi 未覆盖/未充分覆盖）

1. **语义层矛盾**：Kimi 只要求把弱化写进 §6；对抗审进一步发现 §0/§4 仍在说“保持”，且弱化未进用户拍板项。这是文档定稿前最需要在用户层暴露的问题。
2. **快路径数据入口缺口**：Kimi 认可“×2 冗余可砍”，但没有追问替代枚举怎么变成 bands；这是从“砍冗余”到“新模块可造”之间最短的断链。
3. **取证脚本的可执行性**：Kimi 说 T1 证据需行级复核，但未要求复核结果是“可注入脚本可读”，本审补上这一前置条件。
4. **G2 阈值悬空**：Kimi 未把“降级门阈值”列为取证票交付物，可能使 S9 以“新增态”空置。
5. **测试“红=实现偏离”的表述**：Kimi 点过测试面引用待核，但未指出“零改/红即偏离”会掩盖 rAF 迁移对既有测试时序的真实冲击。

这些不构成退回理由，但需要在终裁措辞中变成可追踪的票面/文档义务，而不是“设计已采纳即自动消失”。
