# AI 开发公司组织操作系统（ai-dev-org）

## 概述

跨项目通用的「AI 软件开发公司」组织规范：岗位编制 × 模型路由 × 部门墙
协议 × 成本纪律。第一性原理：执行者必然犯错——组织设计目标是让错误在
合入前现形、每个决定可追溯。**用户只对接一个岗位（主控）**，其余岗位由
主控单一调用（铁律见 references/06 §2）。本技能=loop-engineering 升级
替代件（组织视图+管道视图合并，旧件已归档）。

## 岗位速查（终表见 references/07）

| 岗位 | 通道 | 档位/tier 记法 |
|---|---|---|
| 主控（+PM 子模式） | 主会话 | 会话宿主模型；唯一用户对接岗 |
| 拟定者 drafter | 派发器 `--role drafter` | prime（路线级设计拟定，零仓库接触） |
| 实现者 | 会话内子代理 | 意图档位+欠账记账（定档不可强制，见下） |
| 门一 gate1-reviewer | 派发器 `--role gate1-reviewer` | audit（隔离一审，只喂自包含 diff 包） |
| 门二 | 会话内子代理 | 意图档位+欠账记账（异构优先） |
| 审核者 auditor-readonly | 派发器 `--role auditor-readonly` | debt-readonly（兜底/欠账只读审） |
| SRE 诊断岗 sre-diagnostic | 会话内只读子代理 | 取证/冻结提取/e2e 红 triage；禁写禁臆断 |
| 设计岗 design-reviewer | 会话内图像通道 | 意图档位 session:multimodal-exp+欠账记账（宿主可配模型则按其配置入口执行）；方向级决策留用户 |

（岗位编制=8；人类用户=裁决位不计入编制——同 references/06 §1/07 §1 表注。）

供应商事实（源序/端点/套餐/配给）**一律看 org-config**（默认件+
项目覆盖件 `.zcode/org-config.json`），本件零硬编码。会话内子代理无
model 参数=环境限制：意图档位声明+「环境限制统一档」欠账是**账本强制

## 10. 烤验机关（对抗拷问的流程化——2026-09-10 W4）

> 烤验文化：对抗拷问不是刁难而是义务——审查者的工作是找茬，找不出
> 茬=没尽责；执行者的工作是假设明示，把没验证的判断暴露给拷问者。
> 本节把该文化从「纪律要求」升级为「流程机关」（可机检/可扫描）。

- **烤验触发表**（SKILL.md 同名节）：批次类型→强制对抗位映射；派发前
  自检三问（命中位/源异构性/欠账补还）——任一未过不得派发收口。
- **假设位明示**：主控简报/任务书中的关键假设（对用户意图的理解/
  对既有行为的判断/对环境事实的认定）须逐条标注「假设：…」并列入
  派发包请对抗位优先拷问；审查报告须含「假设拷问」节——假设未被
  拷问=烤验未过。假设被证伪=回炉触发条件之一（§5）。
- **红旗自动扫描**（`scripts/health-scan.mjs`，纯本地零派发；收口前
  必跑，RED=0 方可收口）：
  - ①欠账未还（RED）：账本 exhaust 行后同项目无补还 ok 行——06 §4
    「连续两个关键批未补还=升级用户」的机检前置；
  - ②连续同源（RED）：尾窗 ok 全部同源且 ≥3 批——异构对抗退化
    （关键批须换异源或显式记欠账）；
  - ③预算超限（RED，给了阈值时）：`--budget <alias>:<maxOutTokens>`
    各源累计 out 超阈即红；无阈值时输出各源用量汇总（INFO）作为
    配给判断输入。
- **回炉轮数联动**：回炉超限（§5 上限）事件=health-scan 之后的必查项
  （超限终止留人升级用户，不静默消化）；换源事件在台账标注后由
  扫描器②追踪其后批次的源多样性。

## 1. 事实分层（并入 08 §1 寻址表「产品文档」行，本节为细则）

| 文档类 | 唯一真相源 | 生成规则 | 禁止出现处 |
|---|---|---|---|
| 需求规格 | `docs/spec/`（五问产物，见 §3.1） | 手写（intake 五问落盘=立案前置物） | 交接书正文复述（交接书只留指针） |
| 用户手册 | `docs/manual/` | 手写骨架+截图位（见 §3.2） | 与实现细节耦合（每个 UI 像素级描述=维护地狱） |
| API 文档 | 代码注解→生成物 | **锚定生成器**（OpenAPI 类）：手写只做注解与概述，路由/参数/类型由工具生成 | 手抄端点清单（与代码双源必漂移） |
| 变更日志/发布说明 | `CHANGELOG.md` | 每战役收官追加（§2） | 事后补写（记忆漂移=失实） |

## 2. 生命周期（与战役节奏挂钩——不设独立周期）

- **立项时**：intake 五问（07 §2 PM 动作 1）的产物直接落 `docs/spec/`
  ——需求规格不是「以后补的文档」，是立案前置物。
- **每战役收官即回写**（同 02 §3「收官即回写」条款）：功能面变化
  →手册对应节+CHANGELOG 追加；契约面变化→API 注解重生成。禁止
  「事后补文档窗口」——攒批补写=失实之源。
- **腐化体检**：并入 08 §4 触发式体检——手册引用的界面/入口还在吗、
  生成器输出与代码一致吗（生成物过期=CI 应红）。
- **裁决通道**：文档取舍（写不写/写多细）=用户裁决面候选，随战役
  收口攒批呈报（复用 08 §4 通道）。
