> 定位：回答三件事——**哪类事实住在哪份文档**（单一真相源的地址簿）、

## 1. 事实分层寻址表（哪类事实住哪——双源漂移的根治面）

## 2. 多项目归并指针化手册（四步）

1. **盘点映射**：项目文档群逐件对照 §1 寻址表 → 每件三选一建议
   （**承接**=项目真相源保留／**指针化**=重复段改指针+一行差异注记／
   **废弃**=过时件）+理由+预计动作，产出**全量映射表**——漏一件=
   中间态双源。盘点范围须含项目根全部 .md 群与 docs 子树。
2. **裁决**：三选一属用户裁决面（裁决权限三分法负面清单）——代理只
   起草映射表呈报，**禁代裁、禁裁决前动正文**。
3. **一次性执行**：裁决后在**单一提交**内完成全部指针化（禁分批渐进
   ——中间态=双源最长暴露窗）；废弃件走归档三件套（重定向页+字节校验
   快照+迁移清单，形态见技能自身迁移先例）。
4. **机检兜底**：ORG-SEG 预算自检必跑；有 grep 门禁的项目加一条
   「指针化对照」检查（项目文档中与技能 references 重复的通用原理
   段落=红，白名单登记例外）。

**词汇差异处理**：项目与技能的术语差（如 闸↔门审、R 轮↔回炉轮）=
新增**双向词汇映射表**挂项目宪法头部，历史原文零改动——映射表是
桥，不是改写令。

## 3. 历史件禁改写红线

- **适用面**：一切已成档的过程记录——旧交接书/briefs/审计档/战役报告/
  已并入 git 历史的文档/commit message。
- **理由**：它们是审计链与决策溯源的载体（P7/D2）；改写比删除更糟
  ——删除在 git 历史仍可考，改写制造「当时就是这么说的」伪证。
- **唯一合法动作**：追加（新文件/新段标注日期）或归档；发现历史件
  有错 → 新增勘误件引用原 file:line，**禁原地修改**。
- 新写文档引用历史词汇时用映射表括注（如「闸（=门审授权）」）。

## 4. 文档腐化体检（触发式+定期）

- **触发式**：技能 references 版本升级或项目宪法修订后，对照 §1 寻址表
  扫指针化漂移——被指文件还在吗/内容还匹配吗/新增了正文复述吗。
- **定期**：每战役收口随教训回流查四项——①基线数字与台账一致
  ②指针零死链 ③双源复发扫描（新写的通用原理段落）④stale 文档
  （连续两战役未引用且内容过时=候选废弃，入映射表待裁）。
- **记录**：体检结论一行入项目账本（`event=doc-health`），发现即治。
