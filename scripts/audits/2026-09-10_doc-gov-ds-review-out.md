产物二文件名写 `waterprint/.workflow/adapt-brief-...md`，08 §5 也记录在 `waterprint/.workflow/`；但任务书正文反复将工作档案根、必读 MIGRATION.md、历史件红线范围写成 `E:\class\智水蓝图\.workflow\`（缺少 `waterprint` 一层），并称“仓库外目录”“父目录档案对代理不可见”。若 .workflow 实际在 `waterprint` 内，则这些绝对路径错位，红线对象会指向错误目录，必读清单第 5 条不可达；若 .workflow 实际在 `E:\class\智水蓝图\` 下，则它与 `waterprint` 内的仓库及 `.gitignore`（第 42 行）如何作用也不自洽。“本任务书所在目录不入库”只能解释 `waterprint/.workflow`，不能解释父级 `.workflow`。建议：确定唯一的 .workflow 实际位置，全文统一绝对路径；若任务书确实放在 `waterprint/.workflow`，历史件根、MIGRATION.md、gitignore 说明均应指向该目录；若有内外两个 .workflow，需说明其分工，否则零上下文新会话无法无歧义判断红线范围与读取对象。

## 二、应修级（W）

**[W1] 阶段 0c 与“裁决前禁动任何正文”字面冲突（产物二 §0-2、§0.2、阶段 0c）**
§0.2 禁令第 2 条说“裁决前禁动任何正文（阶段 1 末为硬停点）”，但阶段 0c 在硬停点之前直接修改项目宪法 `AGENTS.md`（插入 ORG-SEG 模板）。尽管可理解为任务书对 ORG-SEG 插入已事先授权，但文本未声明该例外及边界，忠实执行者会陷入“听 0c 还是听禁令”的两难；恶意/误解代理也可能援引 0c 为“可动正文”开口。建议修订：将禁令限定为“除阶段 0 明列动作外，裁决前禁动任何正文”，并确指 ORG-SEG 插入与建档不受 §0.2 裁决前置约束。

**[W2] “零历史件改动”机检手段存在盲区（产物二 §2 阶段 2、§6 DoD；08 §3）**
DoD 用 `git diff` 自查历史件改动，但 `git diff` 默认只比较工作区/暂存区与 HEAD，若历史提交被 `commit --amend`、`rebase` 等改写，`git diff HEAD` 仍可无输出，无法证明“已并入 git 历史的 commit message/文档”未被伪证。建议：阶段 0 开始时记录初始 HEAD commit hash（及关键历史件 hash/行数），DoD 增加 `git rev-parse HEAD` 与基线一致、必要时用 `git log --oneline --all` 核对提交链未被改写；`.workflow` 外 docs 归档件若已入库，另加文件级校验。

**[W3] 三选一对“历史归档件/非文档件”不适用，造成盘点范围与红线冲突（08 §2、§3；产物二 §0.1、§1）**
阶段 1 要求对 `docs/` 全子树逐件出“承接/指针化/废弃”，但 §0 禁令第一条又规定本项目 docs 已归档件一律原样。已归档历史件不能“指针化/废弃”，又不属于“承接=项目真相源保留”，三选一在语义上无合法出口；若漏盘则违反 08 “漏一件=中间态双源”。同理，盘点范围含 `mkdocs.yml` 等非 .md 配置文件，08 的三选一没有覆盖配置类对象的处置列。建议：为历史归档件增加“保持原样/仅登记”态并明确产出动作；对非文档配置单独说明处理方式（如仅登记导航变更或不入映射表）。

**[W4] 08 §1 寻址表“唯一真相源”列出现多候选且体检基准倒挂（08 §1、§4）**
“进程状态”唯一真相源写成“台账/registry/最新一份交接书”三个并列对象，与“唯一”字面冲突；用户裁决原文又同时给“台账 Ruling 行/ADR”两个处所。§4 体检第①项“基线数字与台账一致”未说明基线数字口径的唯一真相源是项目宪法还是台账——按 §1，基线数字口径在项目宪法，台账应引用宪法而不是被当作一致性基准。建议：明确 registry/交接书为“索引/快照”而非并列真相源；体检基准改为“台账引用的数字与宪法口径一致，且指针无死链”。
