## 发现清单

**【W1】WARN｜`tools/ai-sensor/queue.mjs:96-102`（readJson catch-all）——「不存在/读失败/解析失败」三态合并，静默丢失进度 + 失实诊断（双后果实测实锤）**

- **后果 (a) progress.json 损坏 → 已读进度静默全量重置**。实测序列：`--done p1` 后 `队列：0 篇待读 / 1/1 已完成` → 写入 `{BROKEN` 损坏 progress.json → 重跑输出 `队列：1 篇待读 / 0/1 已完成`，**EXIT=0、零警告**——已 done 篇被静默打回 pending。三读是全库 LLM 重成本操作，静默重置=成本事故面；且用户不知情继续 `--done` 时，markDone 会用 fresh 种子覆写 progress.json，旧进度永久丢失。断点续跑承诺（票面核心语义）在损坏场景下静默失效。
- **后果 (b) manifest.json 存在但损坏 → 报错口径失实**。实测：损坏 manifest 与空目录两种场景输出**逐字相同**（「manifest.json 不存在——导出未完成或目录不对」）。ADR-0011 v1.1 判据是「manifest **存在**=导出完整就绪」——损坏文件在磁盘上存在，却按不存在分支走，用户被误导回应用全量重导（清空重建，GB 级成本）；若真实故障是文件被外部工具改坏，重导修不了根因。
- **修复建议**（约 5 行，纯 IO 面，不动锁定测试）：`readJson` 捕获后按 `e.code === 'ENOENT'` 才返回 fallback；解析/读取失败单独上抛，由 CLI 兜底 `console.error + process.exit(1)`（progress.json 损坏时明示「进度文件损坏，将全量重读」并要求显式确认/手动删除，至少不得静默）。

**【N1】NIT｜`tools/ai-sensor/queue.d.mts:20-24`——CorpusManifest 镜像缺顶层 `exportedAt` 字段**

应用侧实际 manifest 形状为 `{ schemaVersion, exportedAt, papers, errors? }`（`corpus.export.service.ts:210-215` 实证）；d.mts 头注自称「manifest.json 产物契约的镜像消费」却漏声明 `exportedAt: string`。无运行时影响（JSON.parse 对多余字段无害，测试 fixture 同样不含），但未来按 d.mts 理解契约的 zcode 会话会漏知该字段——文档性契约漂移。修复：接口补一行 `exportedAt: string`。

**【N2】NIT｜`tools/ai-sensor/queue.mjs:48/65/120`——schemaVersion 只写不读，无版本守门**

`PROGRESS_SCHEMA_VERSION` 写入每个 ProgressState 但任何读取路径都不校验：读到未知 schemaVersion（未来 v2）的 progress 会按 v1 语义静默处理；`applyDone:65` 更会把任何输入版本**静默降级重写**回 1。版本位存在的全部意义就是守门，当前是「有版本位无版本门」——宪法「禁止依赖默认假设」（默认 progress 永远 v1）盲区。当下唯一版本=1 故无实际触发面。修复：`planSession` 读入后校验 `schemaVersion === PROGRESS_SCHEMA_VERSION`，不匹配 → stderr 报版本不匹配 + exit 1。

**【N3】NIT｜`tools/ai-sensor/queue.mjs:125-132/136-150`——CLI/markDone 输入防御三缺口**

(a) `--done` 不校验 paperId ∈ manifest（manifest 在 markDone 里已读到手上，一行校验可拦打错 ID：现状打印「已标记完成：p-typo」成功假象，幽灵条目仅事后经 staleIds 间接可见，真篇仍 pending 重读）；(b) 未知 flag 静默忽略（`node queue.mjs dir --foo` 按无 flag 跑，用户以为参数生效）；(c) `--done` 零 outputs 放行——SKILL.md「篇级产物落盘后才置 done」纯靠调用方纪律，可加 outputs 非空校验（甚至 stat 存在性校验）拦截。三者合并为输入面完备性缺口。

**【N4】NIT｜IO 面零单测——激活判据语义无覆盖**

「manifest 不存在=不激活」是 ADR-0011 v1.1 唯一激活判据 + INV-18 工具侧语义，但无任何测试覆盖（锁定六用例均纯函数面；queue.mjs 头注/测试头注明文「IO 骨架与纯函数分离，不在单测面」——属票面已知范围，故 N 而非 W）。本次 W1 实测即证明 IO 面行为只有人工探针才能发现。建议后续以注入 fs 或临时目录补 planSession 两分支 + progress 损坏分支最小单测（W1 修复落地时顺带）。
