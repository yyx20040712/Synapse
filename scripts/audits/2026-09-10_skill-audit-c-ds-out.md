## 发现清单

**[B] 1. SKILL.md 与 06 §5 源装载退出码/字段名冲突**
- 定位：SKILL.md「派发与自检」段 vs references/06 §5「源装载校验」。
- 问题：SKILL 写“源装载双校验（uuid+name）不符即 exit 3 无 fallback”；06 §5 写“不一致即 exit 2”且字段为 `uuid_prefix`+`entry_name`。两条权威文本对同一失败路径给出不同退出码与不同字段名，会导致派发器自动化测试、告警判据不可定。
- 修正案：应以实际脚本实现为准统一退出码；字段名统一为 `uuid_prefix`/`entry_name`，两处同步改，并删除“name”这类旧 v1 遗留措辞。

**[B] 2. 设计岗“低档体验套餐”档位与会话内“无 model 参数”铁律相抵触**
- 定位：SKILL 岗位速查「设计岗」、06 §1 分工总表「设计岗」、06 §6「会话内子代理定档限制」、07 §4「设计岗·档位」。
- 问题：06 §6 自述会话内子代理无 model 参数，无法强制指定机型/套餐，只能做“意图档位声明+环境限制欠账”。设计岗却是“会话内图像通道”，07 §4 却写“多模态默认低档体验套餐（易逝额度优先）”，并在“档位”项描述为可执行套餐选择。这会让主控误以为能把设计子代理真实路由到低档体验套餐，而按本技能自己的限制实际做不到，造成档位记假账；06 §6 列举受限制岗位时也未含设计岗。
- 修正案：设计岗归入同一“环境限制欠账”机制；若当前环境真能指定图像模型/体验套餐，需明确其通道与配置入口；否则只可写“意图档位 `session:<描述>`”，并强制落“环境限制统一档”欠账行，不得宣称已按低档体验套餐执行。

**[W] 3. 07 §4 说“系统提示模板内联于下方卡片”，但下方没有实现者/门二模板**
- 定位：references/07 §4 首段「口径注记」vs §4 小节目录（仅 SRE 诊断岗、设计岗）。
- 问题：该段声称“会话内岗（实现者/门二/SRE 诊断/设计岗）……其系统提示模板内联于下方卡片”。实际下方只有 SRE 与设计岗卡片；实现者、门二只有 §1 表格中的职责/禁令摘要，没有系统提示模板，也没有指向既有六段简报/门二模板的明确引用。这给“角色卡终表”留下空白：主控每次派发实现者/门二时需自行补模板，容易漂移。
- 修正案：要么为实现者、门二补完整模板或明确锚定到 references/02 的六段简报与门二审验契约；要么把“内联于下方卡片”限制为 SRE/设计两岗，避免声称与实际不符。

**[W] 4. 07 §1“档位（org-config）”列与 06/02 的 tier 口径不在同一层**
- 定位：references/07 §1 岗位终表 vs 06 §1/02 §9。
- 问题：06 §1 与 02 §9 定义外部岗档位为 `org-config.roles.<role>.tier` 的枚举值（prime/audit/debt-readonly）；07 §1“档位（org-config）”列却写 `roles.drafter`、`roles.gate1-reviewer`、`roles.auditor-readonly`。若把该列当“档位值”读，与 `prime/audit/debt-readonly` 不一致；若它是角色配置对象路径，又不应放在“档位”列。履单、账本 tier 记法容易因字段层错位而混。
- 修正案：07 §1 该列改为“配置路径”，或明确写成 `roles.<id>.tier=<枚举>`，统一到角色档案化后的路径/取值两勿混。

**[N] 5. 岗位数口径缺显式声明**
- 定位：SKILL「岗位速查」表、06 §1 表注、07 §1 表注。
- 问题：SKILL 速查表只列了 8 个岗位行，没有“人类用户”行，也没有“编制=8、人类裁决位不计数”的注；06/07 在表注里才补此口径。审查背景提到“9 岗”时，若不看表注会把“8 岗+人类裁决位”误读为缺员。属口径呈现问题，不是逻辑冲突。
- 修正案：在 SKILL 速查表下方显式标一句“岗位编制 8；人类用户=裁决位不计入编制”，终表/速查表保持同一注释。

## 总评与放行意见

正文整体治理骨架与增量口径大体自洽，04/05 增量对教训的制度化也与 06/07 呼应较好；主要硬伤集中在“SKILL 与 06 的退出码/字段冲突”，以及“设计岗档位描述无法在当前会话内子代理限制下兑现”。上述两处会使执行者得到互相矛盾的机器判据或不可执行的档位承诺，不能直接交付。修正 [B] 项（及建议的 [W] 项）后再审，本包方具备放行条件。
