# 闲时会话开工卡 v1（无人值守连续开发）

> **用法**（填进 Zcode 自动化闲时任务 prompt 框的一行）：
> 「在 docs/prompts/ 找编号最大的 idle-handoff-v\*.md，按其开工」
> 本文=v1 起点，由 2026-08-27 第四段人工会话起草（用户已裁决：闲时连续
> 开发+人工卡点提前决策）。**下一会话的开工卡由上一会话在终局时自写**
> （§6 强制）——编号单调递增，开工时永远取最大编号。
> 两条线的关系：人工会话默认用 next-session-handoff 系列；**若 idle 系列编号
> 更新（含更新实况），人工会话也以 idle 版为准**。闲时会话只认 idle 系列。

## 0. 身份与最高规则（先读本节再动任何东西）

1. 你是**无人值守会话**：用户不在场、不可追问。你的一切产出只能靠落盘文档
   被读到——§6 终局交接书是强制产物，**其优先级高于继续干活**（上下文紧张
   时先写交接书）。
2. **禁用 AskUserQuestion**（无人可答）。一切「想问用户」的内容写进终局
   交接书 §3 待裁决。
3. 效力序：`AGENTS.md` 宪法 > 本文件。本文件仅在 §1 预裁决表的范围内容
   「覆盖等待人工」的语义为「确定性规则/终止」；**不覆盖任何红线**（新依赖/
   新出网 host/修改受锁测试让代码通过/触碰用户真实 userData/eval 类禁令）。
4. 决策法则：遇任何未规定之处——查书面先例（ADR → ROADMAP 裁决节 →
   票面 → docs/invariants.md → 最新交接书）；有则依例并在终局交接书引用
   出处；无先例或先例互斥 → 保守终止（§5），不即兴。
5. 配置自查（宪法开工纪律）：确认自身与将派发的双门子代理处于与人工会话
   **同级**的模型/思考等级——省成本省在闲时窗口，不省在审计质量（宪法：
   等级配错的模型签发的一切裁决视为无效）。

## 1. 预裁决表（人工卡点 → 机器规则；2026-08-27 用户批准的草案固化）

| 原人工卡点 | 无人值守规则 |
| --- | --- |
| push 前问询 | **条件授权**，全满足则直接 `git push origin main`：①`npm run verify` 真退出码 exit 0 ②本单元含 e2e 面时 e2e 全绿 ③双门终审 PASS 且存档 scripts/audits/ ④`git diff --stat` 与本单元范围相符（自查无蔓延）⑤受锁触碰已带 [locked-change] 且 locks:apply 同步。任一不满足=本地 commit 即停（禁 force-push；push 网络失败=记录后停，不重试循环） |
| BLOCKING 审计发现 | 能凭书面先例+机器事实当场处置→处置并在交接书引用出处；否则→终止（§5） |
| 测试/契约问题（改受锁面才能绿） | **立即终止**，不做 [locked-change]（宪法原文留给有人会话） |
| 回炉 ≥2 次 | 终止 |
| 实现歧义（票面未覆盖） | 查先例；无先例→终止 |
| 上下文 60% 边界 | 预告即收尾（写交接书→环境三查→commit） |
| 每会话节奏 | **恰好一个逻辑单元**（工单化整批=一单元；一张实现单=一单元）——宁可短会话多次链，不可长会话深堆 |

> 本表升格为 ADR 留待用户首次人工审查时批准/修订。

## 2. 开工前置

1. 技能清点（宪法要求不变；清单写入终局交接书 §0）。
2. 分级阅读：`AGENTS.md` 重点节；本文件；**你开工所依的 idle-handoff vN**；
   `docs/ROADMAP.md` 对应节；当前任务涉及的 ADR。摩擦常量=所依交接书 §0.5
   （v1 期=next-session-handoff-v5 §0.5 十五条全数有效）。
3. **开工自检**（全过才继续）：
   - 基线 `npm run verify` exit 0，用例数=所依交接书 §1 预期（verify 内部
     自带 ABI 绑定切换，若首跑红多为残留——完整重跑一次自愈；再红=终止）；
   - 并发检测：无 node/electron/vitest 进程占用本仓库路径（有=终止——
     verify 单飞纪律）；
   - `npm run locks:check` 绿。

## 3. 环境纪律（无人值守加强版）

- verify 单飞；**禁裸 `npx vitest`**（一律 `npm run test`——绕过即绕过
  `sqlite-abi use node` 前置，NODE_MODULE_VERSION 假红）；
- unlock→改→apply 周期最短化：同一受锁批次一次 unlock、全部改完即时 apply；
- **会话终局三查**：①ABI 绑定=electron（`node scripts/sqlite-abi.mjs use
  electron`）②`locks:check` 绿 ③`git status` 仅剩登记过的残留目录；
- 禁 `npm run dev`（真实库暴露面）；e2e 一律走 SYNAPSE_USER_DATA 隔离；
- Windows 摩擦（rm 挂死/不可见句柄/回显乱码≠存储乱码）：一律 PowerShell
  Remove-Item 兜底；残留登记勿硬刚。

## 4. 任务序列与双门纪律

- 总序列=当前最新交接书 §2（v1 期=`next-session-handoff-v5` §2：SR2-AI-06~10
  工单化 → AI-06 实现 → …每会话一单元链式推进）。
- **双门审计照常必做**：门一对抗深审（独立子代理）→处置→门二终审；存档
  `scripts/audits/`（已入库，直接 commit）。
- 状态机前置表/plan 门环节（如 06 的 job 态空间表）：票面母本（ADR-0015+
  增容节）有据可依则照译；**有一丝无据可依的设计空白→终止留人**，不得凭
  感觉定态空间（错误地基会传播整条批二）。
- 工单化未过 plan 门的票面草案：终止时以 open 状态照常 commit（票头注明
  「草案：未过 plan 门」），树净优先；下一会话先补门再实现。

## 5. 立即终止条件（终止≠失败，是本模式的正确行为）

触发即执行：停止一切改动 → §3 终局三查 → 写终局交接书（§6）→ 本地
commit（§1 条件授权适用则 push，否则停）。触发清单：
- BLOCKING 无法凭先例+机器事实当场处置；
- 需改受锁测试/契约才能绿；
- 回炉达 2 次；
- 基线 verify 完整重跑后仍红；
- 检测到并发使用/锁态损坏；
- 票面/状态机设计空白无书面依据；
- 上下文接近 60% 边界（预告即收尾）。

## 6. 会话终局交接书（强制——用户不追问，全靠它知道你干了什么）

- **无论何种终局（完成/边界停/终止）必写**：
  `docs/prompts/<写作当日>-idle-handoff-v<N+1>.md`（N=你开工所依版本；
  文件头注明「取代 vN」）。写完 commit；§1 条件授权同样适用该 docs 提交。
- 模板六节，自包含、证据指针化、用户零追问可懂：
  - **§0 实况**：做了什么——提交哈希+message 首行清单；验证证据（verify
    文件/用例数、e2e 数、locks 数）；审计档相对路径；每项关键决策引用的
    先例出处（ADR 条款/ROADMAP 节/票面行）。
  - **§1 基线**：下一会话开工预期数字（verify 用例数/e2e 数/locks 数/
    工单 open 数）。
  - **§2 下一步**：基于实际进度的任务指针（含票面/母本文件位置）。
  - **§3 终止原因与待裁决**（若提前停）：发现原文+机器事实+为何无先例；
    给用户的裁决问题**写成一句话是非题/选择题**（用户回来逐条勾选即可）。
  - **§4 用户新增视检项**（若有——延续战役报告视检清单累计）。
  - **§5 摩擦常量新增**（若有——合并进下一版 §0.5）。
