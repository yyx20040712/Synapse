## 4. 教训行（本段追加——v52 §4 之续）

- **关卡类规则设计期必须先存量形态 dry-run 实证**（F-LINT-01 改向案）：
  「存量零误报」验收项在设计链三跳中均未前置验证（Kimi 风险自认/deepseek
  误报面推演/主控终裁三方齐漏），实现期才暴露 61+6 真命中=一轮实现成本
  +改向决策成本。**验收项存在≠已验证**——涉「存量态」假设的设计书须
  附 dry-run 统计输出（一行 grep 即可前置暴露本案）。
- **「参数间接层」是顺序类 bug 的温床**（F-TOOL-01 crop 上下颠倒案）：
  urlA/urlB 间接命名让 drawImage 顺序语义在调用处不可见；尺寸断言
  （IHDR）对内容顺序盲。修法=语义命名直画（urlBase/urlAfter）+合成
  蓝红图顺序验证（对内容断言而非对元数据断言）。
- **正则负锚的单源固化形态**（F-CSS-02+F-LINT-01 C-8 连续两票沉淀）：
  测试文件=正则真相源+关卡侧文本提取+提取失败哨兵=零复制零漂移；
  配方=`readFileSync(test).match(/CONST = \/(.+)\/FLAGS/)`+null=硬红。
  「规则本体驻受锁测试+消费侧提取」模式可复用于后续负锚。
- **Kimi 网关窗对大包敏感**（F-LINT-01 门一 504 实录）：38KB 审计包
  kimi-main 退避 3 次耗尽（1236s）→备源二次尝试成功（558s）——与 v47
  ~10KB 设计包入窗口径合并理解：**>30KB 包走 Kimi 有 504 风险,审计包
  尽量压 <35KB 或预期备源接管**；switches≠0 不必然是额度耗尽（本段
  403=额度窗/504=网关窗两形态都出现过,处置同=状态机自动换源）。
- **多模态目检对 1px 级差异不敏感**（F-TOOL-01 回炉 1 验证案）：Read
  图像回 CDN URL 时 analyze_image 目检上下两半「几乎一致」——最终裁定
  靠 drawImage 目标坐标代码语义推演（y=0 vs y=h+2 铁证）。**代码语义
  确定性>视觉相似性判断**,图像验证是辅助不是终审。
- **git add 显式列表禁 2>/dev/null 吞错+add 后核对 index 面再 commit**
  （F-LINT-01 收口补提交案）：列表含不存在文件名→git add 整条 fatal
  被吞→四核心文件（C-8 段/INV-11/registry/manifest）静默漏出提交
  3b03d2a4cd,两提交后 git status 才暴露；补提交=已验证终态零新改动
  （f-lint01-closeout-verify.raw.txt exit=0）。「staging 显式列文件」
  纪律补半步：**add 后 `grep '^M \|^A '` 核对 index 面与预期清单一致
  再 commit**——commit 回显的 files changed 数与预期文件数对不上即停。
