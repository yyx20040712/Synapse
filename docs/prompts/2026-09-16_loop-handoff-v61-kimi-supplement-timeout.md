## 4. 教训行（本段追加三条）

- **审包体积=派发时效的主变量**（非流式推理窗口 ~5 分钟硬约束）：大简报必配产出
  预算硬约束（≤4000 tok 生成段 ≈105s+prefill ≈90s<300s 窗口）；「砍输入+限产出」
  双管后 246s 一次成——排障期 5 轮 504 全在症状面打转，根因（undici 300s 内建+
  网关窗口）实证后才知 v1-v3 审包结构必死。
- **证据件原子提交**：未跟踪审包两被并发清理批删除——生成后立即 add+commit 单链
  （压缩被删窗口）；「收口毕未跟踪面为零」是清态纪律，不是「未跟踪件可随意消失」
  的许可。
- **链式命令勿吞红**（verify2 实录）：`cmd; echo $? && git add && git commit` 形态
  中 `;` 使提交链无视 verify 退出码——红态提交后靠 amend 自纠；收口命令模板固化为
  「verify 独立跑→看码→再提交」三步禁链式。
