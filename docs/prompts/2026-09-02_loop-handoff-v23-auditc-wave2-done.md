## 3. 本场方法论资产

- **「上游查证」的档案形态**：逐 tag 拉源码对照（raw.githubusercontent+代理）
  →版本×修复面矩阵+区间单处 diff+官方契约锚（destroy() 文档注释）——「查
  证」不落一句结论而落可复现档案（f-r3-upstream-check.md），门二可直接补包
  复核（门一 W2=证据包外不可核实的教训当场兑现修正）。
- **在档坑亲踩即补正**：tee 管道尾 `$?`（v22 §5 明文）本场重演——补变异
  证据落盘时 exit 标注失真；处置=红证本体以 vitest 自身摘要行为准+补正注
  入档+教训确认「证据落盘一律 PIPESTATUS 或独立裸跑」。**坑会重演——在档
  不等于免疫，落盘动作本身要有 checklist 位**。
- **主控压缩票的三种触发形态**（本场三连用）：门审 W 级证据缺口补锚（F-R3
  变异 A/B/C+A3 reject 用例）——票小、变异面明确、无实现设计空间时压缩票
  直做优于回炉（回炉往返成本>补锚成本）；但压缩票同样要绿+变异红证+还原
  diff 空全链（本场 A3 首版锚误落 guardedDescribe 块=压缩票也要过宪法条款
  的实证）。
- **实现者与主控的并行禁区长线化**：实现者运行期间主控**禁变异任何共享
  测试面文件**（其 npm test 全量会撞上变异态假红）——本场 F-R3 W1 补锚
  刻意等到 A3 实现者完成；外部链门审（ds-call 零仓库接触）是唯一安全的
  并行位。
- **排查票「机制预裁先行」的止损价值**：F-R2e 票面写机制排除项（滚动平移
  不变性=一代入即证伪一族假说）先于探针开工——三波执行时少走一族死路；
  假说预裁+排除项入票面应成为排查票模板段。
