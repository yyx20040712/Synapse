### 2F1. 划选全面失败+0.5~5s 延迟（最高优先）

- **技术路线变迁链（用户点名要系统性分析——三轮变三种机制）**：
  ①官方原生 25% 半透明（pdfjs 默认——重叠 span 逐元素叠绘不均匀，
  F-06 前状态）→②F-06 不透明近似色（遮字——被 P1 复测推翻）→
  ③F-07 原生透明+自绘层（延迟+用户报全面失败）。
- **延迟机制假说（代码级已锚，待运行时证）**：`SelectionLayer.tsx:171`
  selectionchange **200ms 防抖**→`evaluate`→`selectionToAnchor` 全
  文本层 span 遍历（annotation-anchor 唯一 DOM 遍历点——大页数千 span
  时 O(n) 昂贵）；B 案后原生高亮透明=**自绘层成为唯一视觉通道**，
  防抖+遍历+React 重渲串行=0.5~5s。防抖值与遍历成本是两因子，取证时
  分别计时。
- **「全面失败」取证步骤（票面前必做）**：真机截图划选各形态（首字
  划选/跨行/跨栏/大段/快速拖选/与 AI 高亮重叠）多模态评审——自绘层
  到底哪里失（不可见？位置错？色太淡？跨行断裂？）。
- **修法候选（分析后裁决，禁拍脑袋）**：
  - **路线 R1=回退原生半透明**（官方 25% + 保留 AiAnnotationLayer 去
    multiply 的层间修复）：零延迟零维护，代价=重叠 span 轻微不均匀
    （原始缺陷 C 回归但程度轻——用户三轮反馈对照看，「不均匀」从未
    被报为问题，「遮字」「延迟」被报了）；
  - 路线 R2=自绘层优化（immediate 评估/分流防抖/遍历缓存）——保完美
    均匀，代价=继续养复杂度（三轮已证此路脆弱）。
  - **主控预裁倾向 R1**（简单机制优于完美效果——用户三次反馈痛点全是
    机制病不是效果病），待取证确认后票面化；受锁面=reader-text.spec
  F-06/F-07 小票守卫改写（两次 [locked-change] 先例在档）。
- **验收判据（用户口径）**：划选**即时**可见（无感知延迟）+文字可读+
  重叠不加深；e2e 加**反馈延迟预算**（见 L7）。

### 2F2. 脉络方向纠偏——严谨直观+边框编码（原始诉求实为文字溢出）

- **实因（代码级锚定）**：`LineageNodeCard.tsx:78-80` 题名=**单行 SVG
  `<text>`——SVG 文本无自动换行**，长题名必溢出卡框（nodeWidth 三档
  220/260 只是缓解）。**「太丑」的本体从 LG-07 到 LG10 两役都未被识别**
  ——被解读为布局/风格问题，实为文本换行功能缺陷。
- **用户设计要求（逐句转译，票面必须原文引用）**：
  1. 脉络图=**严谨直观**；
  2. **边框颜色区分节点类型与文献重要度**即可——**填充色/渐变/夜幕
    全部画蛇添足**（夜幕星象板方向整体否决）；
  3. 文字必须**在框内换行**（这是原始诉求）。
- **修法方向**：①题名换行=SVG `foreignObject` 内 HTML div（自动换行，
  零依赖）或按字符宽手動分行（纯函数可测）；②视觉重制=**浅色严谨板**
  （回归亮面：白卡+细边框；边框色编码：类型=实线/虚线或蓝/金，重要度
  =边框色阶或粗细——**编码方案票面时给用户 2~3 选**，勿再自裁）；
  ③夜幕系 token/样式保留在 theme.css（夜色侧板 LG10 成果可回收用于
  阅读器暗色主题的未来需求，本役摘除脉络消费）；④auto-fit/分档宽/
  层带结构保留（功能层全部通过）。受锁面：lineage-canvas.test 视觉
  it 必然红（渐变/角饰断言）——[locked-change] 改写守卫。
- **教训关联**：L6（本役最大教训，见 §4）。

### 2F3. 壳层修正（重命名+上边栏+字体）

- **重命名 Synapse Remake→Synapse**：⚠**landmine**：userData 目录名
  派生自应用名（`%APPDATA%/Synapse Remake`）——改名后 app.getPath
  变化=**数据迁移第二轮**（复用 R1-WS1 遗留迁移模式：检测旧目录→
  rename/复制入新路径）。改动面=package.json name/productName+
  main-window 标题+App 品牌位；e2e 断言「Synapse Remake」文本的 spec
  需同步（grep 全仓）。**迁移必须幂等+保留旧目录备份一次**。
- **上边栏布局（ZCode 式）**：应用名称+（可选）当前视图驻顶部横栏；
  **移除侧栏品牌行**（用户：「左上角再来一个名称太奇怪」）。实现=
  App 壳加 header 条（h-9 级）承载名称（+课题名可驻此——与 Workspace
  Switcher 合流评估：切换器上移顶栏 or 留侧栏，票面时给用户两案）。
  注意 33px 纵向空间占用对阅读器 TabBar 的影响（F-05 防线回归面）。
- **字体去花哨**：移除 --font-display 衬线栈消费（年份/标题/品牌/
  页码回标准 UI 字体 Segoe UI/微软雅黑——「学术通用」）；衬线仅可
  保留于数字等宽 tabular-nums（功能性）。theme.css token 保留定义但
  消费位清零，或整token 摘除——票面裁。

### 2F4. 文献库卡片等尺寸

- 现状：grid `auto-fill minmax(340px,1fr)` 单元格等宽，但**卡片高度
  随内容伸缩**（题名两行截断已有 min-height，但 venue/标签数不同→
  高度差）。修法=固定卡高（题名两行截断+venue 单行+标签溢出省略），
  或统一 min/max-height 双向钳制；`grid-auto-rows: 1fr` 兜底。纯 CSS
  级微票（受锁面预期零）。

1. **U1=F1 划选修正役**（最高优先）：取证（截图多模态+延迟计时）→

2. **U2=F2 脉络修正役**：换行机制+浅色严谨板重制（边框编码方案先

   化条款）→三屋→真机复评。
3. **U3=F3 壳层修正**：重命名（含数据迁移）+上边栏+字体（三面同域

4. **U4=F4 卡片等尺寸**（微票，可与 U3 顺手但独立提交）。
5. 每单元三屋全流程；首红/变异日志落盘（methodology §4.1 已固化）；
