# ADR-0008：notes.store 五模块级结构维持分布式状态机（不坍缩）

日期：2026-08-23 · 状态：已裁决——维持分布式状态机不坍缩

关联：docs/invariants.md INV-04、INV-50；行为防线=tests/unit/renderer/notes.store.test.ts 与 ADR-0009 性质测试。

## 背景

notes.store 有五个模块级编辑元数据结构：`pendingEdit`（未保存编辑集合）、`editSeq`（编辑序号）、`touchedFields`（已触碰字段）、`loadedOnce`（首载标记）、`lastEditedAt`（最近编辑时刻）。缺陷清查轮评估过将其坍缩为单一显式状态机（状态×事件→迁移表）的可行性。

## 候选

- 坍缩为单一显式状态机：把五个结构重写为一张迁移表。
- 维持五结构分布式状态机：五个正交坐标各自维护，靠锁定用例与性质测试锁行为。

## 裁决

不坍缩，维持现状。量化依据：

1. **行为已锁定**：五结构支撑的语义由 13 条锁定用例+固定种子性质攻击（12 种子×24 步内容安全/savedAt 单调不变量，ADR-0009）+独立对抗审计覆盖。坍缩=全部跨格序列重推导再验证。
2. **各结构生命周期正交**：pendingEdit 由 edit 打点/save 成功（序号守卫）清；touchedFields 由 edit 打点/save 成功清/整版清/合并保留；editSeq 单调自增；loadedOnce 一次性打点；lastEditedAt 仅取存在性。五个维度不是同一状态机的五个态——是五个正交坐标，其组合才是态空间。坍缩成单状态机需要把 2×2×2×2×2 量级的组合显式枚举（多数组合不可达），表反而比五个布尔更难审。
3. **重构成本高于概念收益**：该模块的验证成本主要在跨格序列枚举，不在结构表达（历史教训：单格逐项全过的迁移表仍在跨格序列丢稿，由独立审查拦截）。重构后需要等量的再审计，概念可读性收益边际。
4. **镜像已收敛**：`NoteDraft.pending` 是 pendingEdit 的响应式镜像（四个同步点显式对偶），显示诚实性问题已在不触碰五结构的前提下解决。

重审触发线：

- 五原件出现**第二次**生命周期缺陷（宪法「同类缺陷二次触发即重构」）；
- 真正的**第六个编辑元数据维度**（参与 pending/touched/seq 语义组合的新坐标）出现；
- 多文献并发编辑（若引入）使组合空间真正需要显式枚举。

现状注记（B4-A 修订）：模块级结构数回为五——第六件 `discardGen`（弃改代际守卫）已随 B4-A 弃改路径退役删除（INV-50 重写：完整弃改入口退役，关 tab 改 unfinalized 二选）。结构数不等于元数据维度数，正交坐标仍为五。纯守卫性结构（代际/互斥类）新增不触发重审，但须随变更在本节登记。

## 后果

- 维持现状；新增编辑元数据须沿用「模块级 Map/Set + NoteDraft 镜像同步点」形状。
- 本 ADR 与 ADR-0009 性质测试共同构成该模块的行为防线。
