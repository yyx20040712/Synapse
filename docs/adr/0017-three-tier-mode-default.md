# ADR-0017：三阶段流程为默认运行模式

日期：2026-08-27 · 状态：已裁决——实现类工单单元的默认执行模式；弱模型领单流程不变，两制按单元类型分流

## 背景

用户原位=「每会话做自己的工单+人工统筹全局」，提出让会话替代工程统筹位：
子代理执行工单、孙代理执行审计、会话只对用户接口业务需求。试点单元（当批
最重的实现单元之一）全链跑通三层分工，数据支撑推广决策：

- 质量：隔离一审结论 0 B/3 W/13 N（严重度分级见 docs/methodology.md §4.4；
  三项 W 全真缺陷——含实现者自裁漏报的 SKILL.md 删减面，被审计拦截回滚）；
  返工 1 轮全处置；终审四清单 PASS。审查密度与返工轮次和旧模式对照单元
  相当——质量持平。
- 成本（账本首录）：子代理合计约 12.53M tokens/41.5 分钟；主控上下文轻量
  （只读报告不读产物）——单会话可承载单元数大幅上升（与同日「会话节奏
  上限取消」裁决〔ADR-0016〕互为配套）。
- 终审独立评估：实现者报告诚实度高；自裁申报制度有效；主控-审计分工
  无漏面。

## 裁决

1. **三阶段流程结构**：主控（会话）=工程裁决+编排+收尾单写者（git/
   registry/locks 唯一持笔）；实现者（子代理）=领工单正文五层规约实现+
   TDD，禁 git/registry；隔离一审+终审（独立子代理）=对抗深审+终审复核，
  独立于实现者。返工 ≤2 轮（超限终止留人）。
2. **裁决权限三分法**（主控职权边界）：有书面先例的工程歧义→主控独裁；
   无先例但可逆不触红线→主控预裁+交接书自裁申报；负面清单/新依赖/出网
   host/受锁测试修改/ADR 级/spec 与现实冲突→留用户。
3. **新测试 always-active 标准**：本流程单元新测试不经 guardedDescribe
   直接常开（实现者碰不了 registry——常开=回归面永不掉线）；guard 机制
   保留给弱模型直领流程。
4. **实现者完成定义补强三条**（试点缺陷清单固化）：①断言级变异红证（单
   token 变异→恰中目标用例红→备份法还原 diff 空——禁 git checkout）
   直接入完成定义，不待审查索要；②自裁申报含「删减面 diff 级自查」项；
   ③派发简报先例池文件清单化（收窄实现者首轮阅读面）。
5. **成本账本强制**：每单元在交接书/专项报告记录子代理 token 与时长
   （实现者/隔离一审/终审分列）——旧模式无账，自本 ADR 起补齐。
6. **用户位置**：业务需求接口+工单正文终审（plan 门逐张过）+验收视检+
   裁决队列——工程细节由主控依第 2 款裁决。
7. **运行手册与模板**：原 docs/methodology.md（2026-11-18 随精简退役，
   有效条款并入 AGENTS.md「工作流」「测试纪律」）；现行单源=AGENTS.md。

## 后果

- 实现类单元默认走三阶段流程；纯文档单元主控直做（无实现面，派发无益
  ——按单元类型自然分流，不前置立法）。
- 同日域归属裁决：AI 家族 IPC 通道**新立 ai_sensor 域**（一次性
  [locked-change] 扩契约测试至 9 域穷举）。
- 双目录 CLI 发现机制与 HEARTBEAT_FRESH_MS=10min/STATUS_POLL_MS=5s 同日
  追认（见 ADR-0015）；INV-26 登记文本同步追认。
