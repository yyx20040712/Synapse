# ADR-0017：三屋模式推广为默认运行模式（主控-实现者-双门）

- 日期：2026-08-27（试点单元 SR2-AI-06 c2bfc4f 当日，用户批准八条待裁决第 5 项）
- 状态：已裁决——实现类工单单元的默认执行模式；弱模型领单流程（AGENTS
  「工单工作流」既有条款）不变，两制按单元类型分流
- 关联：SR2-AI-06 试点全链档案（scripts/audits/ai06-impl.* 四档）/门二终审
  §⑤ 试点三行评估/AGENTS.md「工单工作流」（本 ADR 配套增补）/docs/
  methodology.md §4（运行手册+派发模板三件）/ADR-0016（闲时线同款推广）

## 背景

用户原位=「每会话做自己的工单+人工统筹全局」，提出让会话替代工程统筹位：
子代理执行工单、孙代理执行审计、会话只对用户接口业务需求。试点单元
SR2-AI-06（AI 批二最重单之一）全链跑通三层分工，数据支撑推广决策。

## 试点证据（2026-08-27，c2bfc4f）

- 质量：门一 0B/3W/13N（三 W 全真缺陷——含实现者自裁漏报的 SKILL.md
  删减面，被审计拦截回滚）；回炉 1 轮全处置；门二四清单终审 PASS。
  门审密度与回炉轮次和旧模式对照单（AI-05）相当——质量持平。
- 成本（账本首录）：子代理合计约 12.53M tokens/41.5 分钟；主控上下文
  轻量（吃报告不吃产物）——单会话可承载单元数大幅上升（与同日「会话
  节奏上限取消」裁决互为配套）。
- 门二独立评估：实现者报告诚实度高；自裁申报制度有效；主控-审计分工
  无漏面。

## 裁决

1. **三屋结构**：主控（会话）=工程裁决+编排+收口单写者（git/registry/
   locks 唯一持笔）；实现者（子代理）=领票面五层规约实现+TDD，禁
   git/registry；门一+门二（孙代理）=对抗深审+终审，独立于实现者。
   回炉 ≤2 轮（超限终止留人）。
2. **裁决权限三分法**（主控职权边界）：有书面先例的工程歧义→主控独裁；
   无先例但可逆不触红线→主控预裁+交接书自裁申报；负面清单/新依赖/
   出网 host/受锁测试修改/ADR 级/spec 与现实冲突→留用户。
3. **新测试 always-active 标准**：三屋单元新测试不经 guardedDescribe
   直接常开（K3 威胁模型结构性缺位——实现者碰不了 registry；常开=回归
   面永不掉线）。guard 机制保留给弱模型直领流程。
4. **实现者 DoD 补强三条**（试点缺陷清单固化）：①断言级变异红证（单
   token 变异→恰中目标用例红→cp 备份法还原 diff 空——禁 git checkout）
   直接入 DoD，不待门审索要；②自裁申报含「删减面 diff 级自查」项；
   ③派发简报先例池文件清单化（收窄实现者首轮阅读面）。
5. **成本账本强制**：每三屋单元在交接书/战役报告记录子代理 token 与
   时长（实现者/门一/门二分列）——度量短板（ADR 承认：旧模式无账）
   自本 ADR 起补齐。
6. **用户位置**：业务需求接口+票面终审（plan 门逐张过）+验收视检+
   裁决队列——工程细节由主控依第 2 款裁决。
7. **运行手册与模板**：docs/methodology.md §4（派发三件模板=实现者
   简报/门一指令/门二指令——自试点实战稿固化）；AGENTS.md「工单工作流」
   增补三屋条款（宪法级入口）。
