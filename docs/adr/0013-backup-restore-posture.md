# ADR-0013：备份/恢复姿态（不做自动机制+手动指引）

日期：2026-08-25 · 状态：已裁决——不做自动备份/快照机制，手动备份指引登记在册

关联：AGENTS.md 负面清单（云同步永久不做；可移植性由 md 语料导出覆盖）；ADR-0011（语料投影）。

## 背景

「备份/恢复」从未进任何候选池（治理盲区）。「可移植性由 md 语料导出覆盖」的裁决只覆盖知识产出层（笔记/标注语料），不覆盖受管 PDF 与 SQLite 全库。单人本地应用，磁盘故障=全量丢失是真实风险——须显式裁决而非留白。

## 候选

- 自动定时快照机制：后台作业形态。
- 不做自动机制，登记手动备份指引。

## 裁决

不做自动机制，登记手动指引。量化依据：

1. **自动定时快照违反负面清单精神**：「后台自动网络任务」禁令的同类推论——单人本地应用不做后台作业；且应用运行中复制 SQLite（WAL 模式三文件）存在句柄与一致性风险（拷到半途的快照不可用）。
2. **损失面分层可承受**：
   - PDF 原文件：内容寻址存储（sha256 命名），但可从原始来源再生（用户导入的论文必有出处——arXiv/期刊/本地原件）；
   - 知识产出（标注/笔记）：ADR-0011 md 语料导出可全量导出语义层，人工回填路径存在；
   - SQLite 结构化数据：唯一不可再生面=未导出期间的增量——风险敞口=两次手动备份间隔内的编辑量。
3. **手动路径零成本且可靠**：退出应用后整目录复制即得一致快照（应用不占用句柄）。

### 手动备份指引（登记在册）

1. 数据目录=应用 userData 目录（Windows 下为 `%APPDATA%\Synapse\`——应用改名迁移后的现行口径，见 ADR-0020；含 SQLite 库与受管 PDF 目录）；
2. 最佳实践：退出应用后整目录复制到异盘介质；频率与「可接受的编辑损失敞口」对齐（建议每次重要笔记节点的当日）；
3. 恢复：整目录回拷即恢复全库（含 PDF/标注/笔记/进度）；仅 md 语料回填=人工重录路径（不建导入器——恢复场景低频，导入器的一致性审计成本不划算）。

### 复审条件

用户文献规模增长到「不可再生文献占比高」（扫描版/私有 PDF 无出处）→ 重评「手动触发的快照导出」功能（用户点击触发，不违负面清单——与 npm run smoke:installer 同模式的显式动作）。触发线未触发前维持现状。

## 后果

- 现状补记（2026-11-18）：手动姿态之外，应用内已另有快照导出/导入面
  （snapshot 域——加密信封、可选导入合并），与整目录复制互补；本 ADR
  「不做自动机制」裁决不变。

- 本 ADR 即备份姿态的单一真相源。
- 设置页不展示数据目录路径（避免向 renderer 暴露路径——INV-07 受信边界同精神），仅声明「数据保存在本机」。
