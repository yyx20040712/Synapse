## 1. 十二原理

### P1 防线先于功能

git 基线、CI、测试基线、宪法四件事在第一行业务代码之前完成——防线的价值不在
好看，在于让 AI 的错误在合入前现形（事故档：三个项目「一次失败的三次重演」
根因即此）。本仓库形态：骨架期即建 locks sha256 只读+三机检+受锁尾注制度，
此后每个特性战役都在防线内打。

### P2 规则必须机检可达

「文档 + 自动化执行才是纪律」——写进 .md 而没有检查的规则是建议。每立一条
纪律，同步寻找它的机检形态；机检优先级阶梯：**lint/CI > 单测 > e2e > 架构
评审**（越靠左越不可绕过，登记册三档状态即按此分档）。证据：B4 防线把「未
裁决工单不得入场」从文字变成 check-tickets 拒绝；「接缝注册成对」从注释变
成 keymap.test 12 用例；反过来，INV-02 的 blanket 空 catch 禁令因误伤三处合法
尽力而为而回退为规约化——**机检化本身也要接受证伪**。

### P3 单一真相源，禁双源

类型（shared 生成消费）、装配（R12：corpus md 只准一个装配纯函数）、排序
（INV-24：一个比较器）、文案常量、保存状态推导（save-status 单点）——两份
等价声明靠注释对齐必然失守，矛盾时删一份。机检形态：check-quality 跨域白
名单（受控例外显式登记）、check-tickets 工单号引用一致性、受锁 sha256。

### P4 状态机前置，跨格序列显式枚举

凡「store+异步+用户输入」，行为规约必须先给态空间×事件全表，并按「跨格
序列」交审计——18 格单格全过而跨格丢稿（U2 五轮回炉实证）；表要闭合到
冷门迁移（closeTab 于任意态/超时/被并发顶替：C-05 的 S6 行在 r1 审计被拦
「未实现」，说明**表写了但实现漏了照样会被抓**——这正是表的价值）。
「同类缺陷二次触发即重构」是本原理的退出条款。

### P5 不变量登记分级锚定

跨模块/跨时间的行为不变量一律登记（声明处+强制方式+锚定状态），未登记=
未定义行为。允许规划期**预登记**（INV-16~21 先行入册、随工单翻已锚定），
使设计文档与登记册互相校验。锚定方式按 P2 阶梯选择，状态三档诚实标注
（已锚定/部分/未锚定）——「部分」必须写清洞在哪。

### P6 测试是锁定的合约

先红后绿（恒真断言=假阳性，比没测试更危险）；红证要**实录**（翻状态后
N 用例失败的输出存档）；对未提交实现做变异红证时禁 `git checkout`（文件
备份法）；受锁测试改动走 [locked-change]，发现测试错→报告人类，不得自行
放宽。防作弊 K3：open 工单的测试 skip、翻 done 即激活——实现者若不实现就
翻状态，测试当场红。

### P7 双门独立审计，机器事实终裁

第一门（独立模型 diff 审计）+第二门（主控模型结构化清单复核）。运行纪律：
①简报累积制（审计输入携带全部前轮裁决，防复审拿旧简报误判）；②净增量
diff（多轮回炉禁复用首轮 diff——900s reasoning 截止的根因是 diff 累积膨胀）；
③BLOCKING 可携机器事实**证伪重审一次**（YAML 规范引号标量豁免/exportTo
构建顺序——两例证伪都配对抗用例锁定）；④同一单元回炉 ≤2 次，超限升级
用户（UNDO-01 七轮振荡链的教训：每轮修复引入新修复面时，回归用例与 diff
净增量化是强制止损器）。审计器自身是基础设施（教训档第九节）。

### P8 工单=自包含任务书

五层规约（行为/接口/架构/生命周期/文化）让任何执行者（含下任会话）零考古
开工。接缝锚用 file:line **加符号锚**（行号会漂——C-02/C-06 互改同文件的
实证）；owner=strong 的单元改动面以头注清单为准（「只改一个文件」是弱模型
领单纪律，不得混淆）。工单化批次本身过 plan 门（对规约的审计先于对实现的
审计）。

### P9 战役制交付节奏

工单化（plan 门）→ 逐单实现（TDD+双门+一单元一提交+禁同批多单）→ 收官
（e2e 扩展+ROADMAP/INV 回写+战役报告）。三役（P7-A/B/C）同构验证。战役报告
是知识回流的枢纽：教训 §5 → 下任交接书 §5 → 有普遍性的升格宪法/本册。
收官即回写（ROADMAP ✅ 与基线快照同步），不留「事后补文档」的窗口。

### P10 方案切换=删除旧方案；死代码即删

并存=给下一个读者（人或 AI）制造权威冲突。C-06 库侧笔记编辑面下线是正面
实证：删除组件+受锁测试迁径+登记 file 随契约迁移，三面同步完成才叫「下线」。
配套纪律：提交前确认新文件被引用、重复资产零容忍。

### P11 接缝归责，例外显式化

改动模块 A 必须核对相邻模块 B 对同一行为的声明，两处互斥即停下报告——
C-03 的 r1 BLOCKING（save-status 从固定 paper 语义下沉后被动态 paper 消费未
核对）正是本原理的执行实例。跨域依赖例外一律显式登记（check-quality 白名
单=受控例外的登记处，增删白名单=[locked-change]+注释写明裁决依据）。

### P12 上下文是稀缺资源，按预算工程化

分级阅读（只读清单内文件/节）、指针化（中间产物驻 Temp 只留指针）、单边界
停点（预算不足在战役/单边界停，交接书承接）、摩擦常量化（机检摩擦项写进
开工前置清单，禁每会话重新学费——08-26 实测：一场 P7-C 规模战役 ≈44% 上下
文 ≈ 单会话实际上限）。自我造成的回显也是成本：提交后不复打 log、不拉
commit 长 message。

## 2. 适用边界与成本（何时不这样做）

- **双门与工单化是重武器**：适合「行为不可直觉验证/受锁面大/跨模块接缝多」
  的单元。纯文档、单行修复、探索性脚本不值得全流程——事件驱动缺陷单元走
  取证→态空间→红→绿→双门的压缩路径即可。
- **机检有误伤面**：blanket 禁令会撞合法例外（INV-02 三处尽力而为），回退
  为规约化不是失败而是校准；每次机检化上线先跑一轮全量验证误伤。
- **状态机表不是免费的**：五模块正交坐标坍缩成单状态机反而更难审（ADR-0008
  裁决不坍缩的量化依据）——表前置针对「时序行为」，不是一切状态都要表格化。
- **预登记要克制**：登记册是行为不变量的账本，不是愿望清单；每条都要能写
  出强制方式的候选形态，否则先留在 ADR。

## 3. 四条守则（收束）

1. 先有防线，再写代码（P1）。
2. AI 是放大器：好的工程判断×AI=十倍效率，差的判断×AI=十倍技术债——判断力
   来自可验证的验收、可回滚的版本、可信任的测试（P6/P7）。
3. 重写之前先修流程；同构地，**加新功能之前先补防线的洞**（P2/P5）。
4. 在边界停：会话在单/战役边界收束并交接，而不是燃烧上下文到最后一刻
   （P12）——交接书取代制是这一条的制度形态。

## 4. 三屋模式运行手册（2026-08-27 ADR-0017——试点 SR2-AI-06 实战稿固化）

> 结构与职权=ADR-0017；本节只固化**派发模板三件**与实现者 DoD——主控复制
> 改空即用，模板偏差=回炉主要来源，勿即兴。

### 4.1 实现者简报模板（主控→实现者子代理）

固定六段，缺一段=简报不合格：①身份与禁令（实现者子代理/领单号/禁 git
add-commit-push/禁翻 registry——控制面单写者纪律；**取证也不许触
tickets/**：e2e 守卫解除取证用 spec 备份法 skipIfPending([])——F-02 门一
W1 实录：备份法翻 registry 取证即使还原+申报也属路径失当，再犯同类直接
B）；②必读序（AGENTS→**票面五层规约（=完整任务书）**→ADR 母本→先例池
**文件清单化**（试点缺陷③：逐文件列出路径+看什么，不写「相关先例自寻」））；
③主控裁决（票面范围内澄清逐条给依据——实现者不再自裁这些点）；④纪律
（TDD 红→绿→**变异红证**；npm run test 禁裸 npx vitest；verify 真退出码
落盘（echo exit=$? >> 日志）；**首红与每次变异的原始输出必须各自落盘
成日志**（2026-08-29 LG9 W1：仅报告文字转述=证据缺口，联审推演不能替代
举证）；**多断言禁与行尾注释同置**（一行一断言或注释独占行——WS1 W4
实录：两行粘合换行丢失后断言被 // 吞至行尾永不执行）；禁新依赖；≤500
行；UTF-8；卡点=BLOCKED
停手不自裁）；⑤基线数字（verify 用例数/locks 数——实现者自检参照）；
⑤b **视觉类票面增补**（2026-08-29 LIB 门一 3B 实录：mockup 逐值符合≠
真机成立——中文短题名字号参数失效/色阶断裂只在真机暴露）：收口条件=
**真机截图多模态复评不回退**（分数+逐问题消失核对），票面需写明复评
判据与放行线；
⑥报告契约（全文落 scripts/audits/<单号>-impl.report.md：实现摘要/文件
清单/红证/测试证据/locks 实录/**自裁申报**（含删减面 diff 自查——试点
缺陷②）/疑虑；回复五行内）。

### 4.2 门一指令模板（主控→对抗深审孙代理）

铁律（只读+唯一可写审计档+禁 npm/test）→输入四件（diff 包路径/票面/实现者
报告/证据日志路径——**主控预生成的 diff 文件**，禁让审计者自跑 git 长命令）
→主控已预裁项声明（可攻击但推翻需更强依据）→工单 A~E（母本符合度/宪法
红线/代码与测试质量/报告诚实性（自裁逐条对 diff）/接缝与后续单）→输出
（[B|W|N] 逐条+file:line 证据+统计+总评；回复精简全文在档）。
**按票面类型附加强制审项（2026-08-29 增补）**：
- **挂载/事件消费类**（useEffect 消费闩锁/注册监听器/同步派发事件任一
  出现）：**事件时间线逐帧推演**——静态逐跳逻辑审计放行拦不住「同一
  效应内两条语句先后」的竞态（SR2-LG-08 实录：闩锁消费先于监听器注册
  两行=重发事件自丢失，8s 超时假象为「跳错文章」）。
- **CSS 皮肤类**（样式迁类化/新增交互态）：**hover/selected/disabled
  特异性显式推演**——内联 style 恒压一切类（TH1 B1 实录：hover 提亮
  永不生效）、单类 (0,1,0) 压不过带伪类复合 (0,2,0)（LIB W1 实录：
  选中卡悬停期金 ring 被覆盖）；防线=theme/样式文本断言惯例。

### 4.3 门二指令模板（主控→终审孙代理）

四清单+一：①处置核对（门一全 findings+主控裁决 vs 终态实物——防「说了
没改」）；②母本符合度（票面 vs ADR 逐节）；③宪法红线终审（分层/受锁/
安全禁令/行数/UTF-8/TDD 证据链四档）；④机器面核对（verify 数理一致/locks
manifest/翻 done 推演不红/e2e 面申明）；⑤成本账本行（实现者/门一/门二
token+时长分列——主控从派发回执汇出）。

### 4.4 回炉与收口

- 回炉=主控裁决逐条下发原实现者（SendMessage 续命），一轮回炉一复核（门一
  定点 ADDRESSED/NOT ADDRESSED+新破坏扫描）；≤2 轮，超限终止留人。
- 收口=主控单写：亲验 verify 真退出码（不信任任何代理转述）+locks:check+
  diff --stat 范围→翻 registry→显式列文件提交（[locked-change] 尾注随受锁面）
  →交接书/战役报告记成本账本行。
  **顺序铁律（2026-08-29 WS1 实录增补）**：主控面任何编辑（registry 建单/
  TicketArea 联合/受锁 manifest/invariants）之后必须**重跑 verify 全链**——
  verify 永远是收口的最后一个动作，不得在编辑前跑完就以绿收口（实录：
  registry 编辑后只跑 tickets:check 漏 typecheck，带病提交由下一单元拦截）。
