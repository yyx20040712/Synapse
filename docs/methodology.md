## 1. 十二原理

> 通用原理真相源=ai-dev-org references/01；本节为 Synapse 视角的原理表述与机器化形态对应——每条原理必须锚定至少一种机检/测试形态。

### P1 防线先于功能

git 基线、CI、测试基线、宪法四件事在第一行业务代码之前完成——防线的价值不在好看，在于让 AI 的错误在合入前现形（多项目共同教训：无前置防线时同类错误反复重演）。本仓库形态：骨架期即建 locks sha256 只读锁+机检+受锁尾注制度，此后每个特性专项都在防线内打。

### P2 规则必须机检可达

「文档+自动化执行才是纪律」——写进 .md 而没有检查的规则只是建议。每立一条纪律，同步寻找它的机检形态（先例：未裁决工单不得入场=check-tickets 拒绝）。机检优先级阶梯：**lint/CI > 单测 > e2e > 架构评审**（越靠左越不可绕过，登记册三档状态即按此分档）。机检化本身也要接受证伪：blanket 禁令误伤合法例外时回退为规约化是校准不是失败（先例：blanket 空 catch 禁令因误伤合法尽力而为写法而规约化）。

### P3 单一真相源，禁双源

类型（`src/shared/` 生成消费）、语料投影装配（md 投影只准一个装配纯函数，接口契约=ADR-0011）、排序（INV-24：一个比较器）、文案常量、保存状态推导（save-status 单点）——两份等价声明靠注释对齐必然失守，矛盾时删一份。机检形态：check-quality 跨域白名单（受控例外显式登记）、check-tickets 工单号引用一致性、受锁 sha256。

### P4 状态机前置，跨格序列显式枚举

凡「store+异步+用户输入」，行为规约必须先给态空间×事件全表，并按「跨格序列」交审计——单格逐项全过仍可能在跨格序列丢稿（典型：「合并落地→补存失败→再加载」序列丢中间态）。表要闭合到冷门迁移（如 closeTab 于任意态/超时/被并发顶替）——表写了但实现漏了照样会被审计抓，这正是表的价值。「同类缺陷二次触发即重构」是本原理的退出条款。

### P5 不变量登记分级锚定

跨模块/跨时间的行为不变量一律登记（声明处+强制方式+锚定状态），未登记=未定义行为。允许规划期**预登记**（先入册、随工单更新为已锚定——先例=INV-16~21），使设计文档与登记册互相校验。锚定方式按 P2 阶梯选择，状态三档诚实标注（已锚定/部分/未锚定）——「部分」必须写清洞在哪。

### P6 测试是锁定的合约

先红后绿（恒真断言=假阳性，比没测试更危险）；红证（=先让测试红一次以证明该测试能失败的证据）要**实录**（更新状态后 N 用例失败的输出存档）；对未提交实现做变异红证时禁 `git checkout`（用文件备份法）；受锁测试改动走 [locked-change]，发现测试错→报告人类，不得自行放宽。防作弊机制（弱模型直领流程专用）：open 工单的测试 skip、工单更新为 done 即激活——实现者若不实现就更新状态，测试当场红；strong 工单（三阶段流程）新测试一律 always-active，不经 guardedDescribe。

### P7 独立两级审计，机器事实终裁

隔离一审（独立子代理只凭完整 diff 做对抗式审计）+终审（另一独立子代理复核一审结论并做实证验证），两级定义与职权见 §4。运行纪律：①简报累积制（审计输入携带全部前轮裁决，防复审拿旧简报误判）；②净增量 diff（多轮返工禁复用首轮 diff——diff 累积膨胀会耗尽审计上下文）；③BLOCKING 结论可携机器事实**证伪重审一次**（证伪须配对抗用例锁定）；④同一单元返工 ≤2 次，超限升级用户——每轮修复引入新修复面时，回归用例与 diff 净增量化是强制止损器。审计器自身是基础设施：其自身缺陷独立处理，不与被审单元混同。

### P8 工单=自包含任务书

五层规约（行为/接口/架构/生命周期/文化）让任何执行者（含下任会话）零考古开工。接缝锚用 file:line **加符号锚**（行号会漂移）。owner=strong 的单元改动面以头注清单为准（「只改一个文件」是弱模型领单纪律，不得混淆）。工单化批次本身过 plan 门（对规约的审计先于对实现的审计）。

### P9 专项制交付节奏

工单化（plan 门）→逐单实现（TDD+独立两级审计+一单元一提交+禁同批多单）→收尾（e2e 扩展+ROADMAP/INV 回写+专项报告）。专项报告是知识回流的枢纽：教训节→下任交接书教训节→有普遍性的升格宪法/本册。专项收尾即回写（ROADMAP 完成标记与基线快照同步），不留「事后补文档」的窗口。

### P10 方案切换=删除旧方案；死代码即删

并存=给下一个读者（人或 AI）制造权威冲突。「下线」的完成判据=删除组件+受锁测试迁径+登记 file 随契约迁移，三面同步。配套纪律：提交前确认新文件被引用、重复资产零容忍。制度预防：工单/设计书引入平行新实现路线时，工单正文必须显式声明**并存理由+退役触发线**；无退役触发线的并存=返工项（多路线交互面是乘积级复杂度源——复杂度审计见仓外档案区 `/home/yyx/synapse-archive/docs-2026-10-28/reports/2026-09-11_architecture-complexity-audit.md`）。

### P11 接缝归责，例外显式化

改动模块 A 必须核对相邻模块 B 对同一行为的声明，两处互斥即停下报告（典型形态：某语义从固定值改为动态推导后，下游消费方的既有声明未随之核对）。跨域依赖例外一律显式登记（check-quality 白名单=受控例外的登记处，增删白名单=[locked-change]+用户级裁决（COMPOSITION_ROOT_ALLOW 冻结规矩，§4 治理指标段单源）+注释写明裁决依据）。

### P12 上下文是稀缺资源，按预算工程化

分级阅读（只读清单内文件/节）、指针化（中间产物驻临时区只留指针）、单边界停点（预算不足在专项/单边界停，交接书承接）、摩擦常量化（机检摩擦项写进开工前置清单，禁每会话重新学习）。自我造成的回显也是成本：提交后不复打 log，也不再次输出超长提交说明。

## 2. 适用边界与成本（何时不这样做）

> 同构通用版=ai-dev-org references/05 §3；差异=第 4 条「预登记要克制」为 Synapse 不变量册特有条款。

- **独立两级审计与工单化是重型手段**：适合「行为不可直觉验证/受锁面大/跨模块接缝多」的单元。纯文档、单行修复、探索性脚本不值得全流程——事件驱动缺陷单元走取证→态空间→红→绿→独立审计的压缩路径即可。
- **机检有误伤面**：blanket 禁令会撞合法例外，回退为规约化不是失败而是校准；每次机检化上线先跑一轮全量验证误伤。
- **状态机表不是免费的**：多个正交坐标坍缩成单状态机反而更难审（ADR-0008 裁决不坍缩）——表前置针对「时序行为」，不是一切状态都要表格化。
- **预登记要克制**：登记册是行为不变量的账本，不是愿望清单；每条都要能写出强制方式的候选形态，否则先留在 ADR。
- **登记册形态规约**：INV 条目单条超长（≈400 字级）=语义已超登记册形态、实为微型 ADR——新增条目到此规模即拆 ADR 化（条目瘦身一句声明+指针→ADR 详述）；存量 INV-27（三 kind 全景长文）为历史叙述红线例不回拆，其模型演进另见 ADR-0014。

## 3. 四条守则（收束）

1. 先有防线，再写代码（P1）。
2. AI 是放大器：好的工程判断×AI=十倍效率，差的判断×AI=十倍技术债——判断力来自可验证的验收、可回滚的版本、可信任的测试（P6/P7）。
3. 重写之前先修流程；同构地，**加新功能之前先补防线的洞**（P2/P5）。
4. 在边界停：会话在单/专项边界收束并交接，而不是消耗上下文到最后一刻（P12）——交接书取代制是这一条的制度形态。

## 4. 三阶段流程运行手册（ADR-0017；原称三屋模式）

> 结构与职权=ADR-0017（三阶段流程：实现→隔离一审→终审。**隔离一审（历史称门一）**=实现完成后由独立子代理只凭完整 diff 做对抗式审查；**终审（历史称门二）**=另一独立子代理复核隔离一审结论并做实证验证；主控=编排会话——唯一对接用户、唯一有权派发工单与子代理）。本节固化**派发模板三件**与实现者完成定义——主控复制改空即用；模板偏差是返工的主要来源，勿即兴。通用模板版=ai-dev-org references/02 §4/07；本节为 Synapse 实例（含 ⑤a~⑤i 项目条款）。
> [test-refactor] 测试重构专项票规约：双尾注 `[locked-change][test-refactor]`+CI 范围闸+指纹门（契约面 ⊇ 机检口径），详见 `docs/design/2026-09-11_f-testref00-design-final.md`。
> 治理八指标（口径单源=本段）：每份交接书基线段滚动携带 8 个指标——test:src LOC 比／locks 文件数／registry open-done 计数／audits 体量／.git 体量／reader 占 src 比（行数分母含 CSS）／COMPOSITION_ROOT_ALLOW 条数／模块级单例清单数（清单单源=INV-70 附件，随其滚动）。用途=治理层预算盘点，勿为盘点新增常驻脚本（半机械盘点不值得机件）；滚动载体=交接书/接力板基线段两形态通用。
> **COMPOSITION_ROOT_ALLOW 冻结规矩**：白名单冻结，新增例外=用户级裁决（[locked-change]+裁决指针），主控/实现者不得自裁扩列。
> **交接书固定段——事故档回流行**：每份交接书教训行段（交接书/接力板批次日志两形态通用——载体节号随模板版本，勿硬编码）固定增「事故档回流」状态行：本批教训已回流/未回流 `AI辅助开发经验教训.md` 逐条标注（未回流写明触发场次）；回流判据=教训具有「当初为什么立这条规则」性质。

### 4.1 实现者简报模板（主控→实现者子代理）

固定六段，缺一段=简报不合格；工单属视觉/交互/公式/改值/存量态类时，在 ⑤ 段后追加 ⑤b~⑤i 对应条款（见本节末）：

- **①身份与禁令**：实现者子代理/领单号/禁 git add-commit-push/禁改 registry——控制面单写者纪律。**取证也不许触 tickets/**：e2e 守卫解除取证用 spec 备份法 `skipIfPending([])`——备份法改 registry 取证即使还原+申报也属路径失当，再犯同类直接 B 级。
- **②必读序**：AGENTS→**工单正文五层规约（=完整任务书）**→ADR 母本→先例池**文件清单化**（逐文件列出路径+看什么，禁写「相关先例自寻」）。
- **③主控裁决**：工单正文范围内的澄清逐条给依据——实现者不再自裁这些点。
- **④纪律**：TDD 红→绿→**变异红证**；`npm run test` 禁裸 npx vitest；verify 真退出码落盘（`echo exit=$? >> 日志`）；**首红与每次变异的原始输出必须各自落盘成证据日志**（仅报告文字转述=证据缺口，推演不能替代举证）；首红须**全量套跑口径**——定向子集跑红=降档证据须申报；证据日志统一 **`.raw.txt` 后缀**写入仓外档案区 `/home/yyx/synapse-archive/scripts-audits/`（`.log` 后缀被根 .gitignore 静默拦）并在批次日志登记文件名清单——证据件禁提交入仓；**多断言禁与行尾注释同置**（一行一断言或注释独占行——两行粘合换行丢失后断言会被 `//` 吞至行尾永不执行）；禁新依赖；≤500 行；UTF-8；卡点=BLOCKED 停手不自裁。
- **⑤基线数字**：verify 用例数/locks 数——实现者自检参照（预期数字写入前手算留痕，口径见宪法完成定义段）。
- **⑥报告契约**：报告全文落仓外档案区 `/home/yyx/synapse-archive/scripts-audits/<单号>-impl.report.md`（实现摘要/文件清单/红证/测试证据/locks 实录/**自裁申报**（含删减面 diff 自查）/疑虑）；回复五行内。

按工单类型追加的规约条款（⑤b~⑤i，任一适用即入简报）：

- **⑤b 视觉类**：收尾条件=**真机截图多模态复评不回退**（分数+逐问题消失核对），工单正文需写明复评判据与放行线；多模态通道缺失环境的替代形态=无阈值像素差分+DOM 状态转储（「在画但看不见」类缺陷以选区态 vs 基线态全屏差分客观裁定——色值/面积/位置可量化）。
- **⑤c 视觉方向级决策前置——用户反馈逐句转译表**：重设计/换隐喻/换主题类工单必须①把用户反馈**原文逐句**列成「原文→设计动作」转译表入工单正文；②方向级决策须有**用户口头发言/裁决记录**佐证方可全量落地（无记录=先出 2~3 个候选方案请用户选——mockup 多模态评审是设计者自证闭环，不是用户校准位）。
- **⑤d 交互类反馈延迟预算**：交互路径工单正文验收段必须写明「pointer/选区事件→视觉反馈」的预算（如 ≤100ms 级判定标准与 e2e timeout 收紧/单测计时锚形态）。结构性最优解=视觉通道脱离 JS 链路（原生渲染，ADR-0019）。
- **⑤e 公式类推演「合法数据形态可达性」**：涉数据约束的公式/判定类规约，工单正文必须附一段「在全部既有不变量（INV 册）约束下该公式可达吗」的推演——不可达=规格本身错误，非实现问题（例：树单父约束下合法图入度恒 ≤1，「入度 ≥2」判定恒不可达）；单测夹具不得绕过 service 守卫直喂非法态（假绿机制）；verify 绿≠公式活。
- **⑤f 纯 CSS/皮肤级变更同走真机实景验证**：一切改样式值的工单同走视觉复评，且真机验证必须在**有真实数据量的实景**跑（空态验证≠背书）——「纯 CSS 级受锁面零」的判断会漏掉布局语义副作用。
- **⑤g 改值类工单正文必须显式清点「值→派生」耦合链**：清点法=①grep 行高系数（×1.3 类）；②盒高/碰撞盒字面量中的**非整数值**（37.05/12.35 即派生痕迹）；③估宽/估高基准常量。派生族与主值同票迁移，禁以「容差声明」名义半迁（碰撞盒语义=防重叠设计意图，非显示容差）。
- **⑤h 改值工单正文的视觉验收=定向 diff 三件套**：①像素差分带对位（16px 块网格定位器——变化带须逐带归属预期组件区，意外带=返工；Playwright 三坑：about:blank 加载 file:// 静默挂死须 goto file:// 原源页／file:// 页 canvas 污染须 `--allow-file-access-from-files`／中文路径须 pathToFileURL）；②差分区 crop 目检（0 肉眼可见意外差=亚像素重排噪声与真缺陷的分界）；③DOM 计算样式断言（变化组件 computed 值=裁决锚值——最硬一环；已有探针清单无该维度时须补断言探针）。
- **⑤i 涉「存量态」假设的设计书附设计期存量实证**：凡规则/关卡/负锚（负锚=禁词清单 grep 反向锁定，命中即红）类设计书含「存量零误报/零命中/全过」类存量态假设，设计书必须附一行 grep/walk 实测计数输出——设计期即前置暴露「验收与事实互斥」（验收项存在≠已验证）。

### 4.2 隔离一审指令模板（主控→对抗深审子代理）

- 铁律：只读+唯一可写审计档+禁 npm/test。
- 输入四件（均主控预生成）：diff 包路径/工单正文/实现者报告/证据日志路径——禁让审计者自跑 git 长命令。diff 包生成纪律：新文件仅 `git add -N`、跟踪修改件零 add——先 add 再 diff 会把改动送进 staged 区致 git diff 视野静默缺件；生成后以 `--stat` 文件数与 git status 核对。
- 主控已预裁项声明：可攻击但推翻需更强依据。
- 审计工单 A~E：母本符合度／宪法红线／代码与测试质量／报告诚实性（自裁逐条对 diff）／接缝与后续单。
- 输出：[B|W|N] 逐条+file:line 证据+统计+总评；回复精简、全文在档。
- **按工单正文类型附加强制审项**：
  - **挂载/事件消费类**（useEffect 消费闩锁/注册监听器/同步派发事件任一出现）：**事件时间线逐帧推演**——静态逐跳逻辑审计放行拦不住「同一效应内两条语句先后」的竞态（如闩锁消费先于监听器注册两行=重发事件自丢失）。
  - **CSS 皮肤类**（样式迁类化/新增交互态）：**hover/selected/disabled 特异性显式推演**——内联 style 恒压一切类；单类 (0,1,0) 压不过带伪类复合 (0,2,0)。防线=theme/样式文本断言惯例。

### 4.3 终审指令模板（主控→终审子代理）

四清单：①处置核对（隔离一审全部 findings+主控裁决 vs 终态实物——防「说了没改」）；②母本符合度（工单正文 vs ADR 逐节）；③宪法红线终审（分层/受锁/安全禁令/行数/UTF-8/TDD 证据链四档）；④机器面核对（verify 数理一致/locks manifest/更新 done 推演不红/e2e 面申明）。

### 4.4 返工与收尾

- 返工=主控裁决逐条下发原实现者（同一线程续用），一轮返工一复核（隔离一审定点 ADDRESSED/NOT ADDRESSED+新破坏扫描；返工裁定全为 N 级的免审路径见下）。返工 ≤2 轮，超限终止留人。
- 严重度分流（隔离一审/终审发现）：B 级=本域必修返实现者；W 级=主控二选一（本域必修／域外登记立独立工单本批不修——域外登记须 rulingLink+目标批次，单批 ≥3 条须收尾单明示理由）；N 级=主控亲笔处置或域外登记，不触发实现者再进入（随已触发返工顺带处置不受限——N 单独不触发再入）。
- 返工轮口径：计数锚=同一工单生命周期内实现者再进入次数（重派/拆单/改名不重置；触发源不影响计数——主控下发与审计条件驱动续轮同计）；设计面与实施面同上限 ≤2，超限终止留人。
- **小同形批量**：同形小改（同类单行修/常量改跨多文件）合为一单一次派发——省整场简报+独立审位成本，不一票一派。
- **N 级免审**（用户裁决所定）：返工裁定的发现构成全为 N 级=主控亲笔+全机检+终审行为佐证即可收尾（免隔离一审复审）；W/B 级在列仍须复审——复审面与再入触发并行不互斥（前者管复审成本，后者管再入触发）。
- 收尾=主控单写：亲自验证 verify 真退出码（不信任任何代理转述）+locks:check+diff --stat 范围核对→更新 registry→显式列文件提交（[locked-change] 尾注随受锁面）。
- **顺序铁律**：主控面任何编辑（registry 建单/TicketArea 联合/受锁 manifest/invariants）之后必须**重跑 verify 全链**——verify 永远是收尾的最后一个动作，不得在编辑前跑完就以绿收尾。
- **health-scan 与 verify 并行不并入**：health-scan（派发流水健康）与 verify（代码质量）对象不同、各自独立，互不入对方完成定义/串行链——防流程规则面被误判为漂移。

### 4.6 豁免台账生命周期

1. 语义：豁免台账稳态=「未冻结退役申请单」（added/retiring 双面差量同域适用）。四态：创建（授权当前差量）→存活（差量可见，check 每轮命中）→冻结（regen 并入基线，条目永久零命中）→清偿（删除；基线快照+git 历史=审计痕迹）。
2. 刷新协议：regen 与死条目清偿**同批同提交原子**；regen→清偿→check 连续执行，窗口内禁 tests/** 编辑。
3. 零命中硬触发：发现零命中且差量永久消失→同批清偿不攒批（判定手段=test-surface check 的 stale 计数〔按豁免条目身份键〕+探针复演）。
4. regen 节奏（OR 先到先触发评估）：(a) 未冻结 ≥100 条；(b) 距上次 regen ≥5 个含测试面变更的收尾批；(c) 主控裁决提前。评估结论=regen 或明示顺延+理由，禁静默。
5. 先行豁免拦截（regen 轴二）=死条目天然阻断面：登记即须命中，漂移当批暴露。

### 4.7 测试锁分级判据与迁移范式

1. 判据四规则（依次执行，任一出结论即停）：R1 值源问——值/形态已在 invariants.md/ADR/共享契约声明→按契约声明精度锁（精确值→精确锁；区间→区间锁）；「待裁决」只入候选清单不自动登记 INV（防棘轮；降级=ADR/主控裁决）。R2 等价改写问——存在「用户可感知行为不变」的实现改写使断言变红（CSS 等价换写/几何计算路径/取整/选择器重构）→松锁候选。R3 指针子规则——指针事件序列编码用户可见交互契约（拖拽阈值语义/pointer capture/点击顺序）→紧；内部 handler 顺序/坐标簿记→松候选。R4 保守缺省——不确定按紧+登记待裁决。口诀：合规重构不改断言=紧；实现微调即红=松。
2. 迁移范式三条：P1 紧锁不动；P2 精确值→优先关系断言（相对锚/视口无关），确需区间时半宽=max(2 CSS px 绝对噪声下限，值源契约推导容差)并附推导注、设契约容差上限（超上限=按紧锁重判），CI 1024/本地 1280 双形态必须同绿；P3 CSS 源文本正则→渲染行为断言，单测环境给不出计算值时退化=「属性名+关键值存在」，退化断言须变异红证防恒真。
3. 每条松化=1 条豁免{reason=判据条款+两问答案，rulingLink=批次档案（仓外归档区）}；新断言变异红证留档。
