# 闲时任务版连续开发协议（idle-loop protocol）

> 版本:v2（2026-09-03 立制 v1,同日用户追认改连续开发制）。蓝本=v27 §2 双倍池
> 排程+AGENTS 工单工作流+七波场首段实战教训。本文档=无人值守闲时段连续开发的
> **执行协议**;交接书链=**排程真相源**——本文管「怎么跑」,交接书管「跑什么」。
> 在场场次不适用本文(视觉决策/token 基建等由在场场次承接)。
>
> **硬事实(v1→v2 的动因)**:代理**无法自测上下文占用**——工具面不暴露该读数,
> 自估体感已被实证不可靠(2026-09-03 首段:主控自估 ~40% 宣称停点触发提前收段,
> 用户实读=16%,运行 ~20 分钟即「休息」,吞吐损失过半)。因此本协议**不含任何
> 百分比预算停点**;连续性靠「每票干净收口」的断点保护,而非靠自判余量。

## 1. 会话链形态（连续开发版）

```
用户开场（每闲时段一次）:
  「按 docs/idle-loop.md 协议,基于 docs/prompts/LATEST.md 继续闲时开发」
        │
        ▼
┌─ 会话连续推进 ─────────────────────────────────────┐
│ ① 开场对账:技能清点(AGENTS 纪律)+git status 三态判定(§6) │
│ ② 读交接书 §2 → 取首项为当前票                          │
│ ③ 票执行:三屋全链 / 主控快票(按票面预标形态)            │
│ ④ 票收口:checklist(§7)+提交 → **立即取 §2 次项**(回 ③) │
│ ⑤ 停止条件(仅此三种,§2):池空/真阻塞/会话被外部终止      │
└──────────────────────────────────────────────┘
```

- **会话内连续推进,不设段界休息**:每票收口(verify 绿+提交+台账)后立即开下一
  票;交接书/LATEST 在票收口时顺带滚动(检查点,非会话终点——见 §5)。
- 检查点粒度:快票每批一更;三屋票每票一更。
- 上下文摘要信号到达时**不停止**:系统自动压缩续窗,当前票照常做完提交,顺带
  把检查点(交接书 §1 增量)写新,然后继续下一票。摘要是续窗机制,不是停止信号。
- 真正的断点保护=每票独立提交:会话任何时刻死掉,损失≤当前未提交的一票(§6 兜底)。

## 2. 停止条件（仅三种——此外永不自停）

1. **任务池清空**:交接书 §2 全项完成+挂起项处理毕 → 写终版交接书收段。
2. **真阻塞**(逐项有处置,处置后仍继续跑而非收段):
   - 需用户裁决的视觉方向级决策 → 挂起该票(纪律①),跳次项继续;
   - 单票回炉 2 次仍不过 → 挂起+卡点记台账,跳次项继续;
   - 门链 exhaust/网络断 → 按 §4 升级路径降级或顺延三屋票,快票面继续;
   - verify 无从解释的红 → 还原本票 diff(宁停勿烂)后**跳次项继续**,非收段。
3. **会话被外部终止**(用户关窗/宿主停止):无需代理配合,§6 中断恢复兜底。

**禁止事项**:禁以「预算 ~N%」「上下文快满」「感觉该收段」等任何自估理由停止
或收段——代理无该读数,自估=2026-09-03 事故根源(用户实读 16% vs 自估 40%,
已二现为制度红线)。会话真正的余量由系统摘要机制管理,与代理决策无关。

## 3. 闲时纪律（六条）

1. 视觉方向级决策零承担(P7-D 全项不入批;执行中遇到即挂起,留在场场次裁决)。
2. e2e/真机面闲时更稳(前台无竞争);非确定红仍按同用例 2 次立案线通则。
3. 每会话首动作=技能清点(AGENTS 开工纪律),清点结果写入交接书成本账本段。
4. **无人值守升级路径**(无法问用户时按此处置,事后申报):
   | 情形 | 处置 |
   | --- | --- |
   | 单票回炉 2 次仍不过 | 挂起该票:diff 还原+卡点记台账,跳 §2 次项 |
   | 门一 Kimi 链 exhaust(三源皆尽) | 降级=只读审子代理(ds-call 头注在案);零可派则主控自审+交接书标注「门一欠账」 |
   | 门二不可达 | 主控亲跑 verify+五帧对账书面复核,标注「门二欠账」;在场场次补审 |
   | verify 无从解释的红 | 还原本票 diff 至干净态(宁停勿烂),指纹记交接书,跳次项 |
   | 网络断(外部链不可达) | 快票继续(主控自审+欠账标注);三屋票顺延 |
   | 环境面疑似损坏 | 先按 AGENTS 诊断纪律(注册表 PATH+绝对路径探针),禁凭会话态断系统态 |
5. **夜间不留半门审提交**:任何提交前该票门审必须完成或该票整体还原挂起。
6. 计数数字(用例数/locks/预算%)落笔前机器实测(wc/grep/任务单元计数);上下文
   占用属**不可测项**,禁落笔自估值(§2 禁止事项)。

## 4. 票执行形态（沿用既有制度,不重写）

- 三屋全链票:主控派发实现者子代理(显式定档,methodology §4 模板)→门一对抗
  深审(Kimi 链 ds-call)→门二终审→主控收口。一段一票起步,连续制下同会话可
  串多票(每票独立走完全链再开下票)。
- 主控快票:N 级清扫型,红→绿→变异红证主控亲做,合批门审。
- 工单化纪律/票面五层规约/状态机前置(涉 store 迁移面先出态空间表)全按 AGENTS。

## 5. 交接书链与检查点

- 命名:`docs/prompts/YYYY-MM-DD_loop-handoff-vN-<slug>.md`,vN 单调递增。
- **`docs/prompts/LATEST.md`=指针文件**(单行指向当前最新交接书),每检查点同步。
- 交接书角色=**进度检查点+排程真相源**,非会话终点声明:§1 本段终态表(verify/
  locks/e2e 数字+票面结果) / §2 下段执行序(**首项=下一票**) / §3 方法论资产 /
  §4 成本账本(模型×供应商×套餐,含技能清点;预算栏只记任务单元计数与欠账,
  禁自估百分比) / §5 环境事实滚动(基线滚动表:verify 文件数/用例数、locks 数、
  e2e 用例数)。
- 基线对账:每检查点 verify 数字须与上检查点衔接(增量=本票新增锚定数可解释);
  对不上=停止提交,先查。

## 6. 中断恢复协议（开场 git status 三态）

| 态 | 判定 | 处置 |
| --- | --- | --- |
| A 干净树+HEAD=交接书提交 | 正常检查点 | 直接取 §2 首项 |
| B 脏树(未提交 diff) | 票中断残留 | `git diff --stat`+残留文件判归属票 → verify:绿=按票面补完走完门审收口;红=可速修则修,否则还原至干净态(未提交面无门审保护,还原安全;未跟踪新文件删除或移 scripts/audits/ 留档),台账记中断指纹 |
| C 干净树但 HEAD≠交接书提交(提交后未及更新交接书) | 检查点中断 | 查该提交是否过门审(台账/审计档):过=补更新交接书;未过=下一票改为补门审(纪律⑤) |

原则:开场对账**先于**任何新开发动作;B/C 态处置完才准开新票。

## 7. 票收口 checklist（全过才准提交）

- [ ] verify exit=0 亲验,数字与基线衔接可解释(§5)
- [ ] 新受锁文件即时 locks:generate+apply(AGENTS 摩擦根治纪律)
- [ ] 工单在 tickets/registry.ts 翻状态(如有)
- [ ] 台账段落落档(audit0-findings.md 对应票)
- [ ] 变异红证还原 diff 空(备份法,禁 git checkout 还原未提交实现)
- [ ] 过程失误如实申报段(有则写,无则省)
- [ ] 交接书/LATEST 检查点滚动(§5)
- [ ] staging 显式列文件提交;尾注按面([locked-change]/[dep-change])
- [ ] **提交后立即取 §2 次项继续**(连续制——无事收段=事故)
