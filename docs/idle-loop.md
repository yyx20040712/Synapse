# 闲时任务版连续开发协议（idle-loop protocol）

> 版本:v1（2026-09-03 立制;蓝本=v27 §2 闲时双倍池排程+AGENTS 工单工作流+七波场
> 首段实战教训）。本文档=无人值守闲时段连续开发的**执行协议**;交接书链=**排程
> 真相源**,两者分工:本文管「怎么跑一段」,交接书管「这段跑什么」。
> 在场场次不适用本文(视觉决策/token 基建等由在场场次承接)。

## 1. 会话链形态

```
用户开场（每闲时段一次）:
  「基于 docs/prompts/<最新交接书> 进行夜间连续开发」
  （LATEST.md 指针文件=零查目录;交接书链 vN 单调递增）
        │
        ▼
┌─ 段（一个会话=一段）──────────────────────────────┐
│ ① 开场对账:技能清点(AGENTS 纪律)+git status 三态判定(§6) │
│ ② 读交接书 §2 → 本段任务单元声明(§4)                     │
│ ③ 票执行:三屋全链 / 主控快票(按票面预标形态)              │
│ ④ 段收口:checklist(§7) → 交接书 vN+1 → 提交             │
└──────────────────────────────────────────────┘
        │ 下一闲时段（同 prompt 换新交接书名）
        ▼
```

- 段=干净收口单位:**每段必以「verify 绿+全部提交+新交接书」终态结束**;段间零
  盘点成本(下一段只读交接书 §2 即接续)。
- 段粒度:快票批(N 级清扫型)一段可多项;三屋全链票(实现者子代理+门双)**一段
  一票**。
- 会话内上下文被系统摘要后可继续(非段界);段界=任务单元完成+收口,不由摘要触发。

## 2. 停点判据 v2（修订 2026-09-03,待用户追认）

v27 用户裁决③「停点维持 40%」的执行层修订——**起因=七波场首段事故**:主控凭体感
宣称「~40% 停点触发」提前收段,用户实读=**16%**,双倍池吞吐损失过半。教训入册:
上下文占用百分比是计数类数字,落笔前须经实测——而代理**无法自测**该值。

**修订规则**:
1. **任务单元制为主**:段以「交接书 §2 首项任务单元完成」为正常终点,不预设
   百分比配额。
2. **两条可观测保护线**(代替体感 40%):
   - 系统摘要信号:会话收到上下文压缩提示后,**当前票做完即收口**(不再开新票);
   - 用户读数:用户在场并给出读数时,以其为准。
3. **禁止体感宣称**:任何交接书/简报写「预算 ~N%」必须给依据(任务单元计数/
   摘要信号/用户读数),无依据只写「任务单元完成即收」。
4. 余量利用:任务单元完成后若会话仍轻(无摘要信号),**续开 §2 次项**为追加
   单元,同样干净收口——闲时吞吐优先。

## 3. 闲时纪律（v27 三条沿用,扩充为六条）

1. 视觉方向级决策零承担(P7-D 全项不入批;执行中遇到即挂起,留在场场次裁决)。
2. e2e/真机面闲时更稳(前台无竞争);非确定红仍按同用例 2 次立案线通则。
3. 每段首动作=技能清点(AGENTS 开工纪律),清点结果写入交接书成本账本段。
4. **无人值守升级路径**(无法问用户时按此处置,事后申报):
   | 情形 | 处置 |
   | --- | --- |
   | 单票回炉 2 次仍不过 | 挂起该票:diff 还原+卡点记台账,跳 §2 次项 |
   | 门一 Kimi 链 exhaust(三源皆尽) | 降级=只读审子代理(ds-call 头注在案);零可派则主控自审+交接书标注「门一欠账」 |
   | 门二不可达 | 主控亲跑 verify+五帧对账书面复核,标注「门二欠账」;在场场次补审 |
   | verify 无从解释的红 | 还原本段 diff 至干净态收口(宁停勿烂),指纹记交接书 |
   | 网络断(外部链不可达) | 快票继续(主控自审+欠账标注);三屋票顺延 |
   | 环境面疑似损坏 | 先按 AGENTS 诊断纪律(注册表 PATH+绝对路径探针),禁凭会话态断系统态 |
5. **夜间不留半门审提交**:任何提交前该票门审必须完成或该票整体还原挂起。
6. 计数数字(用例数/locks/预算%)落笔前机器实测(wc/grep/任务单元计数)。

## 4. 本段任务单元声明

段开工时在交接书(或开工记录)写明:**本段任务单元=§2 第 N 项(+追加项预判)**。
作用:中断恢复对账锚(§6)+收口判据(单元完成=段正常终)。追加单元须在收口前
补记(如实申报,不追溯美化)。

## 5. 交接书链协议

- 命名:`docs/prompts/YYYY-MM-DD_loop-handoff-vN-<slug>.md`,vN 单调递增。
- **`docs/prompts/LATEST.md`=指针文件**(单行指向当前最新交接书),每段收口同步
  更新——开场 prompt 的零查目录机制。
- 交接书固定骨架:§1 本段终态表(verify/locks/e2e 数字+票面结果) / §2 下段
  执行序(**排程真相源**,首项=下段任务单元) / §3 方法论资产 / §4 成本账本
  (模型×供应商×套餐,含技能清点结果+预算依据) / §5 环境事实滚动(基线滚动表:
  verify 文件数/用例数、locks 数、e2e 用例数)。
- 基线对账:每段收口 verify 数字须与上段交接书基线衔接(增量可解释:新增用例
  数=本段新票锚定数);对不上=停止提交,先查。

## 6. 中断恢复协议（开场 git status 三态）

| 态 | 判定 | 处置 |
| --- | --- | --- |
| A 干净树+HEAD=交接书提交 | 正常段界 | 直接接续 §2 首项 |
| B 脏树(未提交 diff) | 段中断残留 | `git diff --stat`+残留文件判归属票 → verify:绿=按票面补完走完门审收口;红=可速修则修,否则还原至干净态(未提交面无门审保护,还原安全;未跟踪新文件删除或移 scripts/audits/ 留档),台账记中断指纹 |
| C 干净树但 HEAD≠交接书提交(提交后未及写交接书) | 收口中断 | 查该提交是否过门审(台账/审计档):过=补写交接书收口;未过=下段首项改为补门审(纪律⑤) |

原则:开场对账**先于**任何新开发动作;B/C 态处置完才准开新票。

## 7. 段收口 checklist（全过才准提交交接书）

- [ ] verify exit=0 亲验,数字与基线衔接可解释(§5)
- [ ] 新受锁文件即时 locks:generate+apply(AGENTS 摩擦根治纪律)
- [ ] 工单在 tickets/registry.ts 翻状态(如有)
- [ ] 台账段落落档(audit0-findings.md 对应段/票)
- [ ] 变异红证还原 diff 空(备份法,禁 git checkout 还原未提交实现)
- [ ] 过程失误如实申报段(有则写,无则省)
- [ ] 交接书 vN+1 全骨架+LATEST.md 指针更新
- [ ] staging 显式列文件提交;尾注按面([locked-change]/[dep-change])
