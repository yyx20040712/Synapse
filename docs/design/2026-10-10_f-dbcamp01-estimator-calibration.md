## 一、方法

- **被测对象**：`src/main/services/ai/ai-estimate.ts` 的真估计器（esbuild 聚合加载，
  脚本零公式重实现）——系数 a=1.0（CJK）/b=0.25（other），整数算术实现。
- **参考口径（代理）**：`Intl.Segmenter('zh-Hans', {granularity:'word'})` 的非空白
  段计数，每段记 1 token（词级代理）。
- **为何代理**：目标分词器（真实 LLM tokenizer）离线不可达——本应用无出网推理
  面且校准须可重复离线执行；词级代理是 Node 内建、零依赖、确定性的最近旁证。
  **已知系统性偏差**：代理把中文按「词」计数（平均 ~1.5-2 字/词），估计器按
  「字」计数（每 CJK 字 1）——纯中文段估计器对代理天然高出约 50-100%；而真实
  BPE 分词器对中文常见 1-1.5 token/字，介于两者之间且偏估计器一侧。因此本档
  偏差数字是「对代理」的偏差，非「对真值」的偏差——方向解读见 §四结论。
- **语料**：3 类×20=60 内嵌样本（中英混排笔记 markdown 形/标注 quote+comment
  形/记忆 title+content 形——均为装配面真实渲染形态）；覆盖纯中/纯英/混排/
  数字/代码标识符/CJK+ASCII 标点/长短跨（全样本码点跨度实测 min=49 / max=172
  ——〔r1 R-W3〕脚本「码点跨度」行）。
- **判定规则**：类平均绝对偏差>20% → 该类超限；任一类超限 → exit 1。

## 三、预算余量复核

### 3.1 片 cap（PIECE_TOKEN_CAP=120）余量——手算式

以各类 estMax（整行渲染形态，含前缀标记）对片 cap 求 余量=120−estMax：

- 笔记类：120−68=52（余量 52 tok；mean 侧 120−51.9=68.1）
- 标注类：120−53=67（mean 侧 120−43.2=76.8）
- 记忆类：120−46=74（mean 侧 120−40.1=79.9）

结论：三类典型样本（≤68 est tok）全部落在片 cap 120 内——**片 cap 对典型内容
不绑定**（截断仅对超长摘要/笔记生效=设计意图）；mean 侧余量 ≥68 tok。

### 3.2 L2 配额算术核对（片数上限 × 片 cap ≤ L2_CAP）

- paper：15 片（note 5+annotation 4+tag 3+metadata 2+folder 1）×120=1800 ≤
  L2_CAP paper=2200 ✓（余量 400=join 分隔符与舍入面）。
- lineage：3 片（graphMeta 2+folder 1——graphMeta 恒空源实际恒 1 片）×120=360
  ≤ L2_CAP lineage=600 ✓（余量 240）。
- global：8 片上限（实际 6 类×top-1=6 片）×120=960 ≤ L2_CAP global=1200 ✓
  （余量 240）。

### 3.3 L3 腿预算算术（本批 TAIL_LEGS——P3 自洽复核）

- paper：500(window)+300(recall)+0(literature)+200(agent)=1000 ✓
- lineage：400+300+300+200=1200 ✓（600 池=300+300——P4 预裁定档）
- global：500+300+0+200=1000 ✓

## 四、结论

1. **系数维持冻结**（a=1.0/b=0.25 不动）——预裁 P-B 生效：对代理的偏差以「过估」
   为主（三类签名偏差全正），过估=预算收紧方向=安全向（截断面早于真实不足面）；
   反向（欠估）才会造成预算超支进入模型上下文。
2. **偏差如实登记**：笔记类 +26.3%（绝对 28.6%）/记忆类 +27.7%（绝对 28.6%）
   超协议线 20%；标注类 19.4% 在界内。主要贡献面=纯中文短样本（代理按词计数
   的结构性欠计——见 §一「为何代理」）。
3. **终校准挂账**：真实分词器落定（对话管线批——出网推理面接通后）以同脚本
   换参考口径重跑；届时若中文侧类偏差仍 >20% 再裁系数调整（需 ADR+行为锁测试
   同批更新：ai-estimate.test 的期望值随系数走）。
