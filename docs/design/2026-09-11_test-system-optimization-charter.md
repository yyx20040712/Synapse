## 0. 定位：本战役解决什么、不解决什么

### 0.1 问题陈述（一句话）

测试套件 **37,037 行 > 应用源码 31,076 行**，且其外部约束（`tests/**` 全部 sha256 受锁）
使「优化测试」这件事**当前在制度上不可做**——想收拾测试债，必须先非法解锁 162 个测试文件；
而解锁的口子一旦开了，又给了 AI「擅自改测试」的通道。**这是一个死结。**

### 0.2 本战役的目标（三条，缺一不可）

1. **拆死结**：把「测试」拆成**契约面（不可动）**与**脚手架面（可动）**，让可动的那半在法律上可优化。
2. **消三种债**：脚手架重复、覆盖倒挂、不确定面。
3. **升一格防作弊**：把「AI 不许改测试语义」从**纪律**（人要读 diff 判断）升级为**机检**（CI 判指纹）。

### 0.3 硬红线（违反 = 整批作废，不设回炉）

- **R1 零 `src/` 变更**：本战役提交的 diff 范围必须 ⊆ `tests/**` ∪ `tests/utils/**` ∪ 本战役新建的机制脚本。
  任何 `src/` 改动 = 越界，回滚重来。
- **R2 断言只增不减**：任何 `expect`、容差（tolerance）只准保留或收紧，**禁删除、禁放宽**。
  技术性重排（合并同类断言）需指纹门证明**断言多重集不缩**。
- **R3 用例只增不减**：`test/describe/it` 用例清单一经基线固化，**禁静默删除**；
  确需删除 = 人类前置裁决 + `[locked-change]` + 在该提交 diff 中显式列出被删用例标题。
- **R4 测试红不改测试**：测试红了，正确处置**仍是**「报告 + 改实现（另立票）」或「报告测试错（走用户裁决）」。
  **严禁**为了让测试变绿而删断言/放宽容差/加 `skip`——本战役不豁免 AGENTS「测试是锁定的合约」一条。

### 0.4 本战役**不是**什么（防越界想象）

- 不是「把 37K 行砍到 20K」——行数不是目标，**重复与倒挂**才是。脚手架合并能净删数千行，但那是副产品。
- 不是「放松受锁制度」——恰恰相反，本战役**新增一道更严的门**（§2），受锁面只增不减。
- 不是「重构 reader 生产代码」——那是另一场战役（上一份审计 §建议 1 的 INV-58 接缝），
  本战役**遇到即挂起**（见 §5 隔离条款）。

### 1.5 机制现状（为什么现在动不了）

- **受锁**：`tests/**` 全部 sha256 入 `locks/manifest.json`；改一个字符即 `check-locks` 红。
  合法流程 = `locks:unlock` → 改 → `locks:apply` → `[locked-change]` 提交。**全量重构 ≈ 166 条 sha 变更**。
- **防作弊 K3**：`guardedDescribe` 靠 `tickets/registry.ts` 状态开关（open=skip / done=activate），
  未知工单号当场抛错；`check-tickets.mjs` 规则 5 校验"guardedDescribe 号 ↔ 被测文件 import 绑定"。
- **本地 verify ≠ CI**：`npm run verify` **不含 `--coverage`、不含 e2e**（CI 才跑 `test -- --coverage` 与 `playwright test`）
  → **本地绿≠CI 绿**，本战役必须本地显式跑 coverage + e2e（§6）。
- **`check-quality.mjs` 扫 tests**（第 50 行）：TODO/FIXME/占位/乱码——重构须零占位、中文 UTF-8 可读。

### 1.6 一条要害判断（本战役的理论支点）

> **现有防作弊机制的威胁模型已经过期，却仍在主导测试治理。**

`guardedDescribe` + 受锁 + `check-tickets` 规则 5 是**骨架期**为「对抗弱模型假装完成工单」设计的
（open=skip，翻 done 即激活，不实现就红）。但现在 **registry 是 0 open / 173 done**——
**这个威胁已经不存在了**（没有 open 工单可假装完成）。

而当前真正的威胁是新的：**在"优化/合并"名义下，静默削弱回归网**——
删一个用例、放宽一个容差、把断言搬进 helper 藏起来、"合并重复"时把两条断言压成一条。
现有机制**对这一威胁零防护**（它只看工单状态与文件 sha，不看断言语义）。

**本战役的核心动作 = 把防作弊的重心从"防假装完成"迁移到"防静默衰减"**（§2）。

## 2. 核心机制设计：测试面指纹门（Test Surface Gate）

> 这是"防止 AI 擅自修改测试"的机器臂——把「不许改语义」从纪律变成 CI。
> ⚠️ 本节是**设计方向**，正式实现须走 §4.5 架构设计链（**Kimi 拟设计书 → deepseek 对抗审核 → GLM5.3 终裁**）。

### 2.1 分层：把测试拆成两类面

| 面 | 内容 | 变动政策 |
| --- | --- | --- |
| **C 面（契约面）** | 用例标题多重集；每用例的 `expect` 表达式规范化多重集；容差字面量；`guardedDescribe` 工单号；用例数 | **不可缩**（只增不减；变更需人类） |
| **S 面（脚手架面）** | imports、局部工厂、`vi.mock`、几何桩、e2e launch/seed、describe 嵌套结构 | **AI 可自由重构**（受 C 面不变约束） |

### 2.2 机制：`scripts/check-test-surface.mjs`（新建，受锁）

- **实现基线**：复用 `check-dup-constants.mjs` 的 AST 路线（TypeScript compiler 已在本仓可用，零新依赖）。
- **抽取**：对每个测试文件解析出：
  1. 用例清单 = 有序多重集 `{blockPath, title}`（`describe/it/test/guardedDescribe/test.skip` 均纳入）；
  2. 断言指纹 = 每用例内 `expect(...)` 的**规范化源文本**多重集（空白归一，字面量保留）；
  3. 容差字面量（数字 + 单位，如 `2`, `1500`, `0.35`）；
  4. `guardedDescribe` 工单号集合。
- **基线**：`test-surface.baseline.json`（锁定）——形如 `{file: {cases:[…], assertions:[…], tolerances:[…]}}`。
- **判定**（CI 门）：
  - `cases_after ⊇ cases_before`（**无静默删除**，新增放行并标注）；
  - `assertions_after ⊇ assertions_before`（**无静默削弱**）；
  - 容差**只准收紧**（数值向"更严"方向变化放行，反向 = 红）；
  - S 面（imports/工厂/mock）**完全不判**。
- **失败语义**：任何 C 面缩减 = 退出 1，输出「缺失的用例/断言 + file:line」。

### 2.3 为什么它能解死结

- 它把"改测试"从**人类信任问题**变成**机器可判定问题**：AI 可以大规模合并脚手架，但**只要碰了断言语义就红**。
- 它与受锁**正交**：受锁管"文件被改过没"（sha），指纹门管"改的是不是语义"（AST）。
  两者叠加 = **"可以动文件，但动不了契约"**——这正是"优化测试而不过界"的形式化定义。

### 2.4 已识别的反模式（门必须堵，直接写进设计书验证项）

| 反模式 | 门如何堵 |
| --- | --- |
| 把断言搬进共享 helper 隐藏 | 设计书须明确「断言不得移出用例体」；抽取器按**用例体内**统计 `expect` |
| `it.each` 参数化导致用例标题消失 | 比较**展开后**用例集（`it.each` 展开），或要求显式申报等价映射 |
| "合并重复断言"顺手删一条 | 断言多重集是 `⊇` 判定，删即红 |
| 放宽容差让 flake 变绿 | 容差单调收紧判定，放宽即红 |
| 新增 `skip`/`only` 绕过 | 纳入 C 面：新增 skip = 红；`only` 由 Playwright `forbidOnly` + vitest 侧新增守卫拦 |

### 2.5 meta 风险（审计器自身）

指纹门脚本**本身受锁**（`scripts/*.mjs` 自动入锁），且其实现须经门一"验证门未被绕过"专项
（例如：抽取器漏掉某语法形态 = 门形同虚设）。**审计器是基础设施**（教训档第九节）——门本身要证伪一次。

## 3. 分层解锁协议：`[test-refactor]` 票类

现有 `[locked-change]` 是"一刀切解锁"（解锁 → 改 → 重锁 → 打标）。本战役新增**测试重构专用票类**：

- **提交尾注**：`[test-refactor]`（+ 因触及受锁面仍带 `[locked-change]`）。
- **CI 附加检查**（新 job 或并入 `lock-change-guard`）：
  1. **范围闸**：本提交 diff 路径 ⊆ `tests/**` ∪ `tests/utils/**` ∪ `tests/harness/**`（新建）∪ 本战役机制脚本；
     出现 `src/**` = 红（R1 机检化）。
  2. **指纹闸**：`check-test-surface.mjs` 绿（C 面无损失）。
  3. **用例闸**：用例总数 ≥ 基线（R3 机检化）。
- **门审重心转移**：门一不再"读 diff 判断有没有偷偷删断言"（那是人肉、不可靠、是审计带宽黑洞），
  而是**验证指纹闸未被绕过**（抽取器覆盖度、展开语义、边界语法）。
- **人类只在两处介入**：①C 面**新增**用例（正常，快速确认即可）；②C 面**缩减**（必须显式裁决，默认拒绝）。

> 关键收益：把门从"审内容"降维成"审机制"，**审计带宽从 O(diff) 降到 O(门)**——
> 这是让"162 个受锁文件的大规模重构"在现有双门制度下**可审**的唯一出路。

## 4. 工作流（Workstreams，按风险升序）

> 排序原则：先做**零断言风险**的 S 面合并（暖场+建立机制信心），再做**纯增**的覆盖闭合，
> 最后做**需判断**的不确定面收敛。设计链票（§8 P0）在前。

### W1 — S 面脚手架合并（**最大 LOC 收益，零断言风险**）

| 目标 | 现规模 | 收敛到 |
| --- | --- | --- |
| `api/client` mock 工厂 | 38 份 | `tests/utils/` 单源 |
| Toast mock 工厂 | ~31 份 | 单源 |
| 局部 `makeX` 工厂 | 94 文件 | 命名规范 + 常用（Tab/Annotation/seed…）下沉 |
| geometry 桩（gCR/gBCR） | 22 文件 | `tests/utils/geometry.ts` |
| e2e `launch/seedPaperRow` | 5+5 份 | `e2e-env.ts` 单源 |
| first-window 迁移配方 | 12 份 | 单 helper |

**产出**：净删行数记账（每提交报 `git diff --stat` 净删）；**C 面零变化由指纹门证明**。

### W2 — E2E 分层（降运行时 + 降移动部件）

- **探针移出默认门**：`z-r2e-probe.spec.ts` + `z-wg1-probe.spec.ts`（**719 行 ≈ e2e 16%**）
  **不是产品测试**，是 flake 捕获仪。改为 **`@probe` 标签 / 独立 project**，默认 `e2e` 不跑，
  flake 复发时一键全跑。依据：已记录 flake 中**有 2 起发生在探针自身**。
- 保留探针**可一键全跑**（反模式：移出后 flake 复发无捕获面）。
- 收敛 launch/seed 重复（与 W1 合并）。

### W3 — 覆盖倒挂闭合（**纯增测试，安全**）

- 为 `src/shared` 补**直接契约测试**（现 0.32，两个最大源文件被间接覆盖）：
  `schemas.ts` zod 边界、`api-surface.ts` 通道完整性/隐藏通道、`app-error.ts` 错误码封闭性。
- 目标：把 0.32 抬到与其他契约面相当（建议 ≥0.8，具体阈值走设计裁决）。
- **纯增测试不受 C 面禁删约束**，但受 P6「每个测试必须能失败一次」（先红后绿）约束。

### W4 — 不确定面收敛（机件化 + 统一助手）

- **flake 台账机件化**：`docs/audits/flake-ledger.json`（或 INV 附属表），字段
  `{spec, case, count, fingerprint, status, first_seen, resolution}`——替代散文计数。
- **统一 `stableRel` 重试助手**：现 `reader-text` 内联的 400ms 预窗+25×120ms 采样+失败响亮，
  下沉为共享 e2e 助手（消同类几何 flake 的各自实现）。
- **成文不变量**：e2e 内**禁截图比对**（现有 0 处 `toHaveScreenshot`），像素 diff 只留 `scripts/audits/` 工具层
  ——把既成事实升格为受检不变量。

### W5 — 运行成本与本地/CI 一致性

- **本地 verify ≠ CI**（本地无 coverage、无 e2e）——本战役强制：重构后**本地显式跑**
  `npm run test -- --coverage` **且** `npm run test:e2e`，真退出码落盘（禁信转述）。
- 评估 vitest 并行/pool 配置（当前未见 pool 设置）——**低优先**，先不引入复杂度。
- **禁止**用加 `retries` 掩盖 flake（retries 是 CI 容忍，不是修复）。

## 5. 隔离条款：「不影响代码实现」如何保证

### 5.1 零 src 变更（R1 的机检化）

由 §3 范围闸强制。本战役**任何**提交出现 `src/**` = 红。

### 5.2 遇到"测试逼着生产代码保形状"时的处置（**关键**）

上一份审计已识别一批**为兼容历史测试而扭曲生产形状**的测试，例如：

| 测试 | 锁住的生产形状 |
| --- | --- |
| `tests/unit/services/lineage-tags.test.ts:66,87` | lineage 草稿 `tags?` 可选字段（"旧版草稿零破坏"） |
| `tests/unit/services/reader-time.test.ts:56` | `secondsDelta` 第三参缺省=0 |
| `tests/unit/renderer/annotation-layer.test.tsx:33-327` | 存量 `rects` 回退渲染路径 |
| `tests/unit/renderer/reader-search-ui.test.tsx:440` | 某可选 prop 的旧占位 span 兜底 |
| `tests/unit/db/migrate-reading-time.test.ts:27` | v7→v8 迁移默认值 0 |

**处置铁律**：

- **不得**在本战役内放宽/删除这些测试来"解耦"——那会同时动测试语义（违 C 面）**和**生产代码（违 R1）。
- 正确路径：**登记为独立"生产-测试解耦票"**（不在本战役），该票**同时**改 `src` 与对应测试，走正常 `[locked-change]` 双门。
- **唯一豁免**：把测试从"依赖生产形状"改为"依赖**显式夹具**"而**不改断言语义**（例如显式构造一个含 `tags` 的对象
  而非依赖 `undefined` 缺省）——这属 S 面，可做，但须**指纹门证明 C 面不变**。

### 5.3 为什么这个隔离重要

避免两件事被搅在一起：**"收拾测试债"** 与 **"改生产行为"**。
混在一起的后果 = 一个提交里既有测试重排又有行为变更，**门审无法归因**，事故无法回滚
（正是上一份审计 §3-M4「兼容性倒逼」指出的、契约刚性把成本转嫁给实现的机制）。
**分票 = 归因清晰 = 可回滚。**

## 10. 一页纸给主控（TL;DR）

- **死结**：测试 37K 行 > 源码，且 `tests/**` 全受锁——想优化就得解锁，解锁就给 AI 改测试的口子。
- **解法**：把测试拆成 **C 面（契约，机检不可缩）** 与 **S 面（脚手架，AI 可自由重构）**，
  新建 `check-test-surface.mjs` **指纹门**在 CI 判 C 面；新增 `[test-refactor]` 票类（范围闸+指纹闸+用例闸）。
- **效果**：AI 可大规模合并脚手架（W1 净删数千行），但**碰断言语义即红**——把防作弊从"读 diff"升为"判指纹"。
- **零副作用**：范围闸强制 **零 `src/` 变更**；遇"测试逼生产保形状"**登记独立解耦票**（§5.2），不在本战役放宽。
- **重心迁移**：旧防作弊（防假装完成工单）威胁已随 registry 归零而过期；新防作弊（防静默衰减回归网）才是当下的真威胁。
- **第一票**：P0 设计链三跳（Kimi→deepseek→GLM5.3）落地指纹门并**自身证伪一次**，再开 W1。
