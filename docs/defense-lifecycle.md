# 防线生命周期登记册

> **为什么存在**：治理面只增不减会让文书负担持续增长——本册给每道开发流程
> 治理防线一个显式的「退役触发器与评审周期」，使撤/并有判可依、有档可查
> （裁决依据=docs/design/2026-09-28_gov-batch-design-final.md §0 D-GOV-16；
> 宪法条款=AGENTS.md「治理面生命周期」）。
>
> **护栏（D-GOV-16）**：防线撤/并一律主控（主控=编排会话——唯一对接用户、
> 唯一有权派发工单与子代理）裁决；登记表「拦截实绩」栏空≠撤除理由——实绩栏
> 是观察记录不是存续资格，防线未触发≠无价值（防的是未发生的事故）。
>
> **登记面界定**：开发流程治理关卡三类=①机检脚本 ②CI 关卡 ③强制文档字段/机制。
> 运行时安全防线（CSP/shell-guard/preload 隐藏面/app-file ACAO 等）**不入本表**
> ——归 docs/invariants.md 与 docs/security.md 所在域分管（域不同源，勿双登记）；
> 仓外/技能侧机器检查（如技能自带机检件）亦不入本表——归属=技能域自身治理。

## 规则区

- **增量登记义务**：新增治理面（机检脚本/CI 关卡/强制文档字段·机制）立案时
  必须附**退出条件与评审触发器**并登记本册——无退出条件者不予创建工单（AGENTS.md
  「治理面生命周期」条款）；本册、宪法条款与日落规则三处治理面变更即按此登记
  （其退役触发器=下方元机制条，非表行形态）。
- **默认评审周期**=随批顺带（收尾轮在台账记注记）+季度全表核；表内「默认」
  即指此，个别差异见表内注记。
- **拦截实绩书写口径**：只填有档可查的真实拦截（出处=提交号/交接书/教训档/
  工单正文）；查不到填「无在档记录」，禁虚构；防线未触发如实记录（护栏见
  说明头 D-GOV-16）。
- done 票 summary 日落（增量规则）：某票收尾更新状态后，历经 3 次交接书批次滚动
  （「批次」=新 vN 交接书 §2 全项标毕的收尾档）仍未再触及的，由当值收尾主控
  在其收尾轮顺带瘦身为「结论句+（全案=tickets/archive/<票号>.md）」——人工判据
  （registry 无日期字段，批次数以交接书 vN 序为轴），不作机检。
  起算点=该票收尾更新状态所在批次**之后**的首个新 vN 收尾档为第 1 批（中途收尾
  当批不计；收尾当批内的触及同样不计入「再触及」）；「再触及」=该票 file 面
  被任何后续提交改动、或其 registry 行/archive 件被修订（门审提及、他票
  纯引用不算触及）。
- 已瘦身票再触及（勘正/回写类）：改对应 archive 件，registry 行结论句仅在结论
  变化时改写；README 索引行同步。
- **退役触发器书写判据**：新登记行禁填「无」——恒设面须注主控裁决指针；存量
  「无」行=③④⑤⑦⑬⑰⑱与①基础段（①为混合式：基础段无退役面+扩段有触发器），
  补注时点=该行被触及**或季度全表核**（先到者，防长期不触及的无限期滞留）。
  有机拦截与变异红证/TDD 红证在实绩栏须分开标注（变异红证=防线载荷自证
  非有机拦截；存量行红证标注随触及统一）。
- **元机制退役触发器**：本登记册、AGENTS「治理面生命周期」条款与日落规则三者
  作为元机制的退役=治理减容机制经季度评审被用户裁决废除/重构——与表行同规
  （撤/并须主控裁决+宪法修订流程）；元机制不享「无退出条件者不予创建工单」豁免，
  其存续即持有本条退出条件。
